# v1.10.0 — 国际化与无障碍

**状态：** Planned  
**唯一主要任务：** 让界面支持多语言，并让键盘、屏幕阅读器与朗读可用（对标项 A9、J1–J5）。  
**前置版本：** v1.9.0

## 用户价值

不用中文的用户能用自己的语言使用软件；不方便用鼠标的人可以只用键盘完成全部操作；视力障碍用户可以让软件把文档读出来，并跟着高亮看。

## 范围

### 范围内

- 多语言：中文、英文；语言即时切换，无需重启。
- 伪本地化测试（长度膨胀 30%、双语混排），防止布局被截断。
- 键盘：全部功能可达，焦点顺序合理，快捷键不与输入法冲突。
- 高对比度主题与"跟随系统"配色。
- 屏幕阅读器支持：控件可访问名称、角色、状态；UIA 树完整。
- 朗读：系统语音合成，逐词高亮，可调速、可暂停、可从当前位置开始。
- 读取 PDF 标签结构（`/StructTreeRoot`）生成阅读顺序；无标签时回退到排版顺序。

### 范围外

- 生成 PDF/UA 合规文件（J6，需要完整标签编辑器）。
- 除中英以外的语言包（结构留好，翻译后补）。
- 手语视频、盲文输出。

## 设计决策

### 文案从第一天起就只允许一种写法

现有代码里已有 `tr()`，但也有硬编码中文字符串。本版本做一次全量清理，并在 CI 加一条门：**新增的界面字符串必须走 `tr()`，否则构建失败**。晚做一次的代价是后面每加一个功能都要返工。

### 伪本地化是布局测试，不是翻译测试

中译英会变长，德译英更长。用"把每个字符替换成带重音的变体并加长 30%"的伪语言跑一遍界面，能提前发现按钮截断、标签换行、对话框撑破——这些问题用真翻译发现得太晚。

### 朗读的逐词高亮必须来自语音引擎事件

按字数估算高亮位置一定会漂移（中英文语速不同）。SAPI 的 `SPEI_WORD_BOUNDARY` 事件给出真实的词边界与时长，高亮直接跟事件走。拿不到事件时（部分语音包）降级为"按句高亮"并说明。

### 阅读顺序优先用标签树，没有才猜

PDF 的 `/StructTreeRoot` 是作者声明的逻辑顺序，比内容流顺序和坐标排序都可靠。PDFium 提供 `FPDF_StructTree_*` 接口。没有标签的文档回退到 v0.9.0 的排版排序，并在无障碍面板提示"本文档无标签结构，朗读顺序为推断结果"。

## 验收标准

- [ ] 中英切换即时生效，全部界面（含对话框、提示、错误）无残留中文/英文。
- [ ] 伪本地化下无控件被截断、无文字溢出（截图逐窗口比对）。
- [ ] 不用鼠标可完成：打开、搜索、批注、保存、打印五条主流程。
- [ ] UIA 客户端能读到每个按钮的名称与状态；焦点不会丢失。
- [ ] 朗读时高亮词与语音同步（偏差 <150ms），可暂停/继续/调速。
- [ ] 带标签文档的朗读顺序与标签一致；无标签文档给出提示。
- [ ] 高对比主题下所有文本对比度 ≥4.5:1。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 语言：英文界面下超长单词、中文界面下英文路径、系统语言为第三种语言时的回退。
- 键盘：Tab 循环、Shift+Tab、Esc 关闭、输入法组合态。
- 朗读：中英混排、数字与符号、超长段落、语音包缺失。

## 安全与隐私

- 朗读使用系统离线语音，不把文档内容发送到任何在线服务。
- 语言包与语音包不随包分发，避免许可证与体积问题。

## 依赖与许可证

- Qt Linguist 工具链（LGPL-3.0，已在清单内）。
- Windows SAPI（系统组件）。

## 风险与回滚

- 风险：字符串清理遗漏导致部分界面仍是硬编码中文；朗读在部分语音包下无词边界事件。
- 回滚：语言可强制锁定中文；朗读入口可隐藏；恢复至 `v1.9.0`。
