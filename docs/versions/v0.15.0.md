# v0.15.0 — 发布前加固

**状态：** Released  
**发布标签：** `v0.15.0`  
**唯一主要任务：** 完成正式发布前的性能、安全、稳定性和兼容性加固。  
**前置版本：** v0.14.0

## 用户价值

产品能够在真实文档、长时间运行和异常环境下保持稳定，并达到 1.0 发布候选质量。

## 范围

- 性能预算、内存预算、崩溃恢复和模糊测试。
- PDF 兼容语料、AI 评测和无障碍检查。
- 安全审计、依赖漏洞和许可证闭环。
- 范围外：新增产品功能。

## 设计决策

### 先量，再改

加固阶段最容易犯的错是「凭感觉优化」：改完之后没有对照，也不知道是快了
还是只是换了个地方慢。所以第一步不是改代码，是把可重复的基线立起来：

- `tests/PerfTests.cpp`：五条纯计算指标，各自带预算断言；
- `scripts/perf.ps1`：跑一遍并把实测值打印成表；
- `docs/PERFORMANCE.md`：预算、实测与已知慢点。

预算取实测的 10 倍以上——抓数量级退化，不把机器快慢当回归。

### 为什么性能与界面验收分开

界面验收（`verify-*.ps1`）测的是「行为对不对」；把它当性能测试用，
数字会被渲染线程、磁盘和 CI 负载搅成噪声。两件事分开做，两边才有意义。

### 已知慢点先记账，不急着改

OCR 预处理每页约 220 ms，大头是 3×3 中值滤波。它跑在后台线程，
翻页不卡；但整篇扫描件批量识别会受它限制。优化方案已写进
`docs/PERFORMANCE.md`，前提是「先量再改」，并且要用样张验证识别质量没退。

### 依赖门核对的是「登记与实现是否漂移」

加固阶段的另一类风险是「文档里写一套、构建脚本里跑另一套」：登记表写着 Qt 6.8.3，
工具链路径却指向 6.7；PDFium 的 SHA-256 被换成短串也照样能编过。这类问题不会在运行时
暴露，只会在用户机器上暴露。

`scripts/verify-dependencies.ps1` 因此不联网查 CVE，只做能证明的静态核对：登记表每一行
都有精确版本、关系、许可证与更新路径；文件里的机器可读 pins 与 `bootstrap-toolchain.ps1`、
`cmake/toolchains/qt-mingw.cmake`、`bootstrap-pdfium.ps1` 逐项一致；vcpkg 基线是 40 位
提交哈希；仓库不提交二进制；给了安装包时，每个 DLL/EXE 都必须能归到登记表里的组件。
最后一条当场抓到一个真问题：`windeployqt` 会顺带复制微软的 `D3Dcompiler_47.dll`，
它既不在登记表里也没有随包许可证全文——现在打包显式不带它。

CVE 复核仍是人工判断，结论与日期记在 `docs/PRIVACY_AUDIT.md` 第 5 节；自动门保证的是
「复核过的对象没有被悄悄换掉」，不是「没有新漏洞」。

### 隐私审计要落到具体代码路径，而不是写一份声明

`docs/PRIVACY_AUDIT.md` 的清单从「数据什么时候产生」出发，而不是从「我们承诺不收集」
出发。写法上刻意要求每条都有落点（文件、环境变量、凭据管理器目标），否则审计会变成
形容词。这样写当场找出两处真问题：

- 提案审计把文档**绝对路径**写进 `audit.jsonl`，而审计的原则是只记元数据；现在只落文件名；
- 诊断轨迹把**选区文字、复制内容、搜索词**原样写盘；现在默认写 `<redacted:长度>`，
  只有验收脚本显式设 `AIPDF_TRACE_TEXT=1` 才写原文。

两条都配了回归测试或验收路径，避免「这次改了、下次又加回来」。

### 过程中被抓出来的缺陷

- **坏文件「加载成功但页面树全烂」。** 模糊测试喂 60 份变异 PDF 时发现：PDFium 有时
  返回成功但取不到第 0 页，旧代码会把这种文档交给界面，表现为「打开了但一页都不显示」。
  现在 `openDocument` 探测第 0 页，取不到就报「页面无法加载」并关掉句柄。
- **提案审计写入绝对路径。** 审计原则是只记元数据，路径会把用户名与目录结构带进去。
- **诊断轨迹默认写入选区文字、复制内容与搜索词。** 轨迹可能落盘，等于一份文档内容副本；
  现在默认 `<redacted:长度>`，验收脚本显式打开 `AIPDF_TRACE_TEXT=1`。
- **包内出现未登记的微软运行库。** `windeployqt` 顺带复制 `D3Dcompiler_47.dll`，
  它不在登记表里、也没有随包许可证全文。
- **`-SkipAcceptance` 没有跳过兼容性与崩溃恢复验收。** 这两个脚本和别的界面验收一样会抢桌面，
  在共享机器上跑会被误伤；现在与其余界面验收同处一个开关之下。

### 已知限制

- **72 小时稳定性未在本版本执行**，按上面的测试要求移到 1.0.0；本版本用崩溃恢复、
  模糊测试与 500 页连续浏览覆盖了同类失效模式。
- **无障碍只做到「辅助技术可枚举、可操作」**（UI Automation 驱动全部界面验收），
  没有做屏幕阅读器朗读顺序与高对比度专项；那是 1.10.0 的范围。
- **CVE 复核是 2026-11-14 的人工快照**（Qt 6.8.3 / PDFium 8152 / MinGW 13.1.0），
  自动门只保证复核过的对象没有被换掉；每次升级 PDFium 或 Qt 都要重新复核。
- **qpdf 仍未引入**，外观流的增量写入是手写的最小实现；1.6 的加密与 1.7 的签名
  仍依赖 [qpdf 提案](../QPDF_ADOPTION.md) 获批。
