# v0.8.0 — 页面管理与安全保存

**状态：** In Progress  
**唯一主要任务：** 实现页面增删、旋转、重排和不会破坏原文件的保存流程。  
**前置版本：** v0.7.0

## 用户价值

用户可以整理 PDF 页面，并在失败时保留原始文档。

## 范围

- 页面插入、删除、旋转、重排。
- 临时文件写入、重新打开校验和原子替换。
- 自动恢复日志和另存为。
- 范围外：内容流文字编辑和数字签名。

## 设计决策

实现方式完全由 PDFium 159 的实测能力边界决定，探针在 `build/probe/page_probe*.cpp`：

| 操作 | PDFium 公开接口 | 实测结果 |
|---|---|---|
| 插入空白页 | `FPDFPage_New` | 页数与尺寸都对，**大纲完全不受影响** |
| 删除页 | `FPDFPage_Delete` | 页数正确；只有指向被删页的那一条书签解析不出目标 |
| 旋转页 | `FPDFPage_SetRotation` | 接口收的是**四分之一圈**（0..3），不是角度；旋转写进文档的 `/Rotate` |
| 移动页 | 没有这个接口 | 实现为「导入副本 + 删除原件」：内容、批注、页面旋转都跟着走 |
| 序列化 | `FPDF_SaveAsCopy` | 写进内存的 PDF 字节，重新打开后页序、旋转、批注都在 |
| 批注标记 | `FPDFAnnot_SetStringValue("NM")` | 可写可读；批注因此能带上自己的 id，页面挪动后仍认得出来 |

**移动页的已知损失**：被移动页上的**内部链接目标会失效**，指向被移动页的链接同样失效，
指向该页的那一条书签也解析不出目标。PDFium 159 没有公开接口能修回来
（没有 `FPDFLink_SetDest`、没有 `FPDFDest_CreateDest`、没有创建链接注释的接口）。
整本重建能把链接修好（PDFium 会重映射目标），但大纲会整个丢掉——
两者只能取其一，本版选了「原地移动」，保住大部分书签。

## 验收脚本的边界

恢复问询是**模态弹窗**：一旦弹出，验收脚本就点不动界面了；
而且验收每个场景都要重启应用，上一轮留下的记录会让每一轮启动都弹框。

- `AIPDF_RECOVERY_DIR`：把恢复日志放到临时目录，各脚本互不干扰。
- `AIPDF_SKIP_RECOVERY_PROMPT`：探针模式，**跳过问询**（记录照旧留着）。
  由 `scripts/AcceptanceProbe.ps1` 统一设置；只有 `verify-pages.ps1`
  的「启动恢复」场景会临时摘掉它，去验真实的问询与重放。
