# v0.8.0 — 页面管理与安全保存

**状态：** Released  
**唯一主要任务：** 实现页面增删、旋转、重排和不会破坏原文件的保存流程。  
**前置版本：** v0.7.0  
**发布标签：** `v0.8.0`

## 用户价值

用户可以整理 PDF 页面，并在失败时保留原始文档。

## 范围

- 页面插入、删除、旋转、重排。
- 临时文件写入、重新打开校验和原子替换。
- 自动恢复日志和另存为。
- 范围外：内容流文字编辑和数字签名。

## 设计决策

实现方式完全由 PDFium 159 的实测能力边界决定，探针在 `build/probe/page_probe*.cpp`：

| 操作 | PDFium 公开接口 | 实测结果 |
|---|---|---|
| 插入空白页 | `FPDFPage_New` | 页数与尺寸都对，**大纲完全不受影响** |
| 删除页 | `FPDFPage_Delete` | 页数正确；只有指向被删页的那一条书签解析不出目标 |
| 旋转页 | `FPDFPage_SetRotation` | 接口收的是**四分之一圈**（0..3），不是角度；旋转写进文档的 `/Rotate` |
| 移动页 | 没有这个接口 | 实现为「导入副本 + 删除原件」：内容、批注、页面旋转都跟着走 |
| 序列化 | `FPDF_SaveAsCopy` | 写进内存的 PDF 字节，重新打开后页序、旋转、批注都在 |
| 批注标记 | `FPDFAnnot_SetStringValue("NM")` | 可写可读；批注因此能带上自己的 id，页面挪动后仍认得出来 |

**移动页的已知损失**：被移动页上的**内部链接目标会失效**，指向被移动页的链接同样失效，
指向该页的那一条书签也解析不出目标。PDFium 159 没有公开接口能修回来
（没有 `FPDFLink_SetDest`、没有 `FPDFDest_CreateDest`、没有创建链接注释的接口）。
整本重建能把链接修好（PDFium 会重映射目标），但大纲会整个丢掉——
两者只能取其一，本版选了「原地移动」，保住大部分书签。

## 验收脚本的边界

恢复问询是**模态弹窗**：一旦弹出，验收脚本就点不动界面了；
而且验收每个场景都要重启应用，上一轮留下的记录会让每一轮启动都弹框。

- `AIPDF_RECOVERY_DIR`：把恢复日志放到临时目录，各脚本互不干扰。
- `AIPDF_SKIP_RECOVERY_PROMPT`：探针模式，**跳过问询**（记录照旧留着）。
  由 `scripts/AcceptanceProbe.ps1` 统一设置；只有 `verify-pages.ps1`
  的「启动恢复」场景会临时摘掉它，去验真实的问询与重放。

### 过程中被测试抓出来的缺陷

- **插页时整个界面卡死。** 页面结构一变就要换掉渲染线程，旧代码写的是
  「`cancel()` 之后 `wait()`」——而 `cancel()` 只作废请求、不叫醒线程：
  线程正睡在条件变量上，停止标志只在析构函数里才置位，主线程于是永远等下去。
  单元测试测不到（那里没有渲染线程），是 CI 的界面验收撞出来的：
  点「插入」之后没有轨迹行，UIA 查找一次要 6 分半。
  修法：线程类加显式 `stop()`（置标志 + 唤醒），停线程的顺序改成
  `stop() → wait() → delete`；并补 `RenderThreadTests` 守住这条路径。
- **命令栏的「页面」在 UI Automation 里找不到人。** 命令栏的按钮是 QAction，
  而 QAction 的对象名不会出现在 UI Automation 里——验收脚本按 `commandPages`
  找按钮，一个都找不到，页面面板里的操作按钮自然也点不到。
  修法：给工具栏里真正的 QToolButton 起对象名（`commandPagesButton`）。
- **命令栏连点两次会把面板关掉。** 命令栏的「页面」「批注」是导航命令，
  却借用了导航栏图标的开关逻辑，看着像功能坏了。
  修法：命令栏改成「切过去并显示」，导航栏图标仍然保留开关。
- **启动时的恢复问询挡住验收界面。** 问询是模态弹窗，而验收每个场景都要
  重启应用，上一轮留下的记录会让每一轮启动都弹框，弹框一挡界面就点不动。
  修法：加 `AIPDF_SKIP_RECOVERY_PROMPT`（探针模式跳过问询，记录照旧留着），
  需要验问询流程的场景临时摘掉它。
- **`verify-m0.ps1` 用了这个脚本里并不存在的 `$WorkDir`。** CI 跑到启动验收
  就挂在这一行。
- **验收脚本的场景之间互相污染。** `verify-pdf` 与 `verify-scroll` 共用同一个
  恢复目录；场景 4 用的文件已经被场景 3 保存成 4 页，页数断言对不上。
- **撤销之后的计数断言写成了 `count=1`。** 撤销之后计数是 0。

### 已知限制

- **移动页会打断链接。** 被移动页上的内部链接目标失效，指向被移动页的链接
  同样失效，指向该页的那一条书签也解析不出目标——PDFium 159 没有公开接口
  能修回来。整本重建能把链接修好，但大纲会整个丢掉，两者只能取其一。
- **恢复日志记的是命令序列，不是文件副本。** 恢复要在原文档的路径上重放：
  文件被移走或改名之后就恢复不了。
- **备份只有一份。** 每次保存把上一份 `.folixa.bak` 覆盖掉，不留历史版本。
- **批注的跨阅读器外观一致性仍不保证。** PDFium 159 无法为新建批注生成合规
  外观流（v0.7.0 的限制），存盘后其它阅读器看到的批注外观可能不一致。
- **页面操作不动已有签名。** PDFium 没有公开接口可保留签名域，
  签名文档被页面操作后签名可能失效。
