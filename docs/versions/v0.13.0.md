# v0.13.0 — OCR 与扫描件问答

**状态：** In Progress  
**唯一主要任务：** 对无可用文本层的扫描 PDF 执行 OCR，并纳入检索和问答。  
**前置版本：** v0.12.0

## 用户价值

扫描合同、票据和历史文档也可以搜索、复制和进行带引用问答。

## 范围

- 本地 OCR Worker、语言包管理和置信度。
- OCR 文本、坐标和索引集成。
- 手动与自动触发策略。
- 范围外：直接重写 PDF 隐藏文本层。

## 设计决策

### 先做「判定 + 坐标 + 接口」，再谈识别引擎

OCR 的难点不在调用识别库，而在三件事：**哪些页需要 OCR**、**识别出来的字落在页面哪儿**、
**怎么取消**。这三件事都跟具体引擎无关，所以先做成可单测的纯逻辑：

| 模块 | 职责 |
|---|---|
| `ocr::ScannedPageDetector` | 判定一页是不是「扫描页」（没有文本层，或文本层少得可怜） |
| `ocr::imageRectToPage()` | 图像像素坐标 → 页面用户空间坐标（PDF 点，原点在左下） |
| `ocr::OcrEngine` | 引擎抽象：`recognize()` / `cancel()` / `isAvailable()` |

引擎实现放在后面接：它只负责「图像进、文字与框出」，其余都在这一层之上。
这样即使将来换引擎（Tesseract / Windows OCR / 云端），判定、坐标和索引都不用改。

### 判定规则：宁可多判，不要漏判

- 文本层字符数为 0 → 扫描页；
- 字符数少于 40 **且** 文本覆盖面积占比低于 5% → 扫描页（页眉页脚常有一行字，
  不能因为「有字」就当成可检索）；
- 其余 → 不 OCR。

「覆盖面积」用文本块包围盒并集估算，比单纯数字符稳：一页只有页码时，字符数小、
覆盖更小，会被判成扫描页；而正文页即使短，覆盖也明显更大。

### 坐标换算必须翻转 Y 轴

PDF 用户空间原点在**左下**，图像原点在**左上**。识别结果是在图像上量的，
回填时必须 `pageY = pageHeight - (pixelY + pixelHeight) / scale`。
这一步写错的表现是「高亮框上下颠倒」，而且只在非对称页面上才明显——所以单独做函数并单测。

### 取消与资源限制是接口的一部分

`OcrEngine::cancel()` 从第一天就在抽象里：扫描件 OCR 动辄几十秒，
没有取消能力的实现会逼着上层在「卡住」和「杀进程」之间选。
每页识别前检查取消标志，识别结果带 `cancelled`，上层丢弃即可。

### 依赖：先不引入，接引擎时再钉版本

仓库的第三方政策要求「版本、来源、许可证可追踪」。识别引擎（优先 Tesseract，
Apache-2.0，预编译 Windows 包）作为独立步骤引入，届时同步更新
`THIRD_PARTY_LICENSES.md`、SBOM 与 `scripts/bootstrap-*`。
本版先保证不接引擎时整条链路可编译、可测试。

## 实施步骤

- [ ] OCR 结果类型与引擎抽象（`src/ocr/OcrTypes.h`、`src/ocr/OcrEngine.h`）。
- [ ] 扫描页判定：`src/ocr/ScannedPageDetector.{h,cpp}` + 单测。
- [ ] 坐标映射：`src/ocr/OcrGeometry.{h,cpp}`（像素 → 页面，翻转 Y）+ 单测。
- [ ] 本地 OCR Worker 与任务队列（可取消、限并发）。
- [ ] 页面图像预处理（灰度、二值化、去噪）。
- [ ] 识别结果接入索引与问答，引用可定位到页面区域。
- [ ] 手动与自动触发策略（打开文档时按判定结果排队）。
- [ ] 界面验收：扫描件可搜索、可问答、可取消。

## 验收标准

- [ ] 无文本扫描件可以搜索和问答。
- [ ] OCR 引用能定位到正确页面区域。
- [ ] OCR 可取消且有资源限制。
- [ ] 软件显示版本为 `0.13.0`。

## 测试要求

- 判定：空文本层、只有页码、正常正文、文本层很短的正文。
- 坐标：等比缩放、非等比缩放、Y 轴翻转、越界裁剪。
- 中英文、倾斜、低分辨率、混排和大批量扫描页（接引擎后补）。

## 安全与隐私

- OCR 默认本地执行；语言包来源及许可证可追踪。
- 识别结果与扫描图属于文档内容，同样受 v0.12.0 的数据策略约束。

## 风险与回滚

- 风险：识别误差可能被模型放大。
- 回滚：恢复至 `v0.12.0` 并删除 OCR 索引。
