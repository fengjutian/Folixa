# v0.13.0 — OCR 与扫描件问答

**状态：** In Progress  
**唯一主要任务：** 对无可用文本层的扫描 PDF 执行 OCR，并纳入检索和问答。  
**前置版本：** v0.12.0

## 用户价值

扫描合同、票据和历史文档也可以搜索、复制和进行带引用问答。

## 范围

- 本地 OCR Worker、语言包管理和置信度。
- OCR 文本、坐标和索引集成。
- 手动与自动触发策略。
- 范围外：直接重写 PDF 隐藏文本层。

## 设计决策

### 先做「判定 + 坐标 + 接口」，再谈识别引擎

OCR 的难点不在调用识别库，而在三件事：**哪些页需要 OCR**、**识别出来的字落在页面哪儿**、
**怎么取消**。这三件事都跟具体引擎无关，所以先做成可单测的纯逻辑：

| 模块 | 职责 |
|---|---|
| `ocr::ScannedPageDetector` | 判定一页是不是「扫描页」（没有文本层，或文本层少得可怜） |
| `ocr::imageRectToPage()` | 图像像素坐标 → 页面用户空间坐标（PDF 点，原点在左下） |
| `ocr::OcrEngine` | 引擎抽象：`recognize()` / `cancel()` / `isAvailable()` |

引擎实现放在后面接：它只负责「图像进、文字与框出」，其余都在这一层之上。
这样即使将来换引擎（Tesseract / Windows OCR / 云端），判定、坐标和索引都不用改。

### 判定规则：宁可多判，不要漏判

- 文本层字符数为 0 → 扫描页；
- 字符数少于 40 **且** 文本覆盖面积占比低于 5% → 扫描页（页眉页脚常有一行字，
  不能因为「有字」就当成可检索）；
- 其余 → 不 OCR。

「覆盖面积」用文本块包围盒并集估算，比单纯数字符稳：一页只有页码时，字符数小、
覆盖更小，会被判成扫描页；而正文页即使短，覆盖也明显更大。

### 坐标换算必须翻转 Y 轴

PDF 用户空间原点在**左下**，图像原点在**左上**。识别结果是在图像上量的，
回填时必须 `pageY = pageHeight - (pixelY + pixelHeight) / scale`。
这一步写错的表现是「高亮框上下颠倒」，而且只在非对称页面上才明显——所以单独做函数并单测。

### 取消与资源限制是接口的一部分

`OcrEngine::cancel()` 从第一天就在抽象里：扫描件 OCR 动辄几十秒，
没有取消能力的实现会逼着上层在「卡住」和「杀进程」之间选。
每页识别前检查取消标志，识别结果带 `cancelled`，上层丢弃即可。

**当前实现只兑现了一半：** `cancelAll()` 能清空排队中的页，但打不断正在跑的识别——
Windows 引擎的子进程是 `recognize()` 的栈变量，引擎侧只能置标志位，最长要等到 120 s 超时。
这一条已记为 [C-10](../OCR_LIMITATIONS.md#c-10-取消名不副实已知缺陷)，不算「已实现」。

### 引擎：先接系统 OCR，再谈随包分发

安装包需要管理员权限、随包分发又要处理许可证与 SBOM，所以这一版先用两条零安装路径：

1. 装了 `tesseract`（PATH 或 `AIPDF_TESSERACT_PATH`）→ 调命令行，读 TSV；
2. 没装 → 用 **Windows 自带 OCR**（`Windows.Media.Ocr`）。

两者都走同一个 `OcrEngine` 接口，换回内置库或隔离 Worker 时上层不用改。
系统 OCR 没有置信度：`meanConfidence` 留 0，不假装「很确定」。

实现在临时目录里生成 PowerShell 脚本调用 WinRT，跑完即删——不需要随包分发原生库。

**系统 OCR 不是「Win10 自带就有」：** 语言包要单独安装，`TryCreateFromUserProfileLanguages()`
还跟着用户首选语言列表走。只装了 en-US 的机器上，中文扫描件不会报错，会返回拉丁垃圾或空结果。
所以它只能当兜底，不能当唯一引擎；探测与文案见 [C-11](../OCR_LIMITATIONS.md#c-11-isavailable-只探测-powershell)。

### 本版接受的妥协

这一版为了「零安装、零新依赖先跑通」，在引擎、输入、结果、任务四层都留了妥协，
其中若干是**已知缺陷**（旋转页静默空结果、取消名不副实、全角标点搜不到、只给 171 dpi）。
逐条记录（现状 / 理由 / 代价 / 偿还条件）见
[OCR 妥协清单](../OCR_LIMITATIONS.md)——本版验收时按那份清单判断哪些能接受。

### 依赖：先不引入，接引擎时再钉版本

仓库的第三方政策要求「版本、来源、许可证可追踪」。识别引擎（优先 Tesseract，
Apache-2.0，预编译 Windows 包）作为独立步骤引入，届时同步更新
`THIRD_PARTY_LICENSES.md`、SBOM 与 `scripts/bootstrap-*`。
本版先保证不接引擎时整条链路可编译、可测试。

- [x] OCR 结果类型与引擎抽象（`src/ocr/OcrTypes.h`、`src/ocr/OcrEngine.h`）。
- [x] 扫描页判定：`src/ocr/ScannedPageDetector.{h,cpp}` + 单测。
- [x] 坐标映射：`src/ocr/OcrGeometry.{h,cpp}`（像素 → 页面，翻转 Y）+ 单测。
- [x] 本地 OCR 任务队列（后台线程、单并发、可取消）——进程隔离留到接引擎时一并做。
      取消目前只对排队中的页有效（[C-10](../OCR_LIMITATIONS.md#c-10-取消名不副实已知缺陷)）。
- [x] 页面图像预处理（`src/ocr/ImagePreprocess.{h,cpp}`：灰度、中值去噪、Otsu 二值化）。
- [x] 识别结果接入索引（`ocr/OcrChunkBridge`：同一套分块器 + `fromOcr` 标记并落盘）；问答复用现有检索。
- [x] 自动触发：打开文档与切页时自动识别一次（每页每次会话一次），另有手动入口。
- [x] 界面验收：`scripts/verify-ocr.ps1`（自动识别、入索引、标 `source=ocr`、文字页不误识别）。

## 验收标准

- [ ] 无文本扫描件可以搜索和问答。
- [ ] OCR 引用能定位到正确页面区域。
- [ ] OCR 可取消且有资源限制。
- [x] 软件显示版本为 `0.13.0`。

## 测试要求

- 判定：空文本层、只有页码、正常正文、文本层很短的正文。
- 坐标：等比缩放、非等比缩放、Y 轴翻转、越界裁剪。
- 中英文、倾斜、低分辨率、混排和大批量扫描页（接引擎后补）。

## 安全与隐私

- OCR 默认本地执行；语言包来源及许可证可追踪。
- 识别结果与扫描图属于文档内容，同样受 v0.12.0 的数据策略约束。

## 风险与回滚

- 风险：识别误差可能被模型放大。
- 风险：系统 OCR 在缺中文语言包的机器上**静默劣化**（返回拉丁垃圾或空结果），
  在旋转页上**静默返回空**——两者都不会报错，用户只会觉得「识别不准」。
  发布说明里要写清这一点，见 [OCR 妥协清单](../OCR_LIMITATIONS.md) 的 C-06、C-11。
- 回滚：恢复至 `v0.12.0` 并删除 OCR 索引。
