# v1.7.0 — 数字签名

**状态：** Planned  
**唯一主要任务：** 支持手写签章与证书签名，并能验证签名有效性（对标项 G5–G7）。  
**前置版本：** v1.6.0

## 用户价值

用户可以在合同上签章，签完的文件别人改一个字就能被验出来；收到带签名的文件时，能看懂"谁签的、什么时候签的、签完之后有没有被改过"。

## 范围

### 范围内

- 手写签章：笔迹/图片 → 外观流 → 签名域。
- 证书签名：PKCS#7 detached，签名域（`/FT /Sig`），字节范围（`/ByteRange`）增量写入。
- 证书来源：Windows 证书存储（个人证书、USB Key/智能卡）。
- 时间戳：RFC 3161（可选，默认关闭，需配置 TSA 地址）。
- 验签：完整性、证书链、时间戳、签名后修改检测（DocMDP）。
- 签名面板：列出全部签名域、状态、签者、时间。

### 范围外

- PAdES-LTV 长期验证（先做 B-B，LTV 留到 2.x）。
- 自建 CA、证书签发、电子签章服务器。
- 批量签章（1.8.0 的批量框架接入后再评估）。

## 设计决策

### 签名 = 增量更新 + 预留字节范围

PDF 签名的结构是：先在文件里留一段空白 `/Contents`（hex），签完之后把 PKCS#7 填进去，同时用 `/ByteRange` 声明"除这段之外的全部字节"。所以签名**必须是增量更新**——一旦全量重写，已有签名全部失效。

这条约束决定了签名要排在 v1.3.0 写入层之后，并且 `DocumentWriter` 要提供"预留占位符"的能力。

### 只用系统密码学，不引 OpenSSL

Windows 上证书、私钥、智能卡都在 CNG/CryptoAPI 里。引入 OpenSSL 只会多一份需要审计和打包的二进制，还得自己管私钥——而私钥本来就该在系统的证书存储里。

代价是暂时没有跨平台签名能力，这与"Windows x64 优先"的发布策略一致。

### 验签要回答三个问题，而不只是"有效/无效"

1. **完整性**：`/ByteRange` 覆盖的字节摘要是否匹配；
2. **身份**：证书链是否能到受信任根；
3. **时序**：签名之后文档是否被修改（增量更新了几次、是否触碰了已签字节）。

只给一个"签名有效"的绿勾是危险的——签名有效但文档被追加过内容，是常见攻击面。所以状态要分开显示，且"签名后已修改"必须是黄色警告，不是绿色通过。

### 时间戳失败不阻断签名

TSA 不可达时，签名照常完成（只是没有可信时间），并在签名属性里记明"未取到时间戳"。反过来会让离线场景完全不可用。

## 实施步骤

- [ ] 签名域创建与外观流（手写、图片、文字印章）。
- [ ] `DocumentWriter` 的占位符预留与回填。
- [ ] PKCS#7 detached 签名（CNG），支持智能卡。
- [ ] `/ByteRange` 计算与增量写入，多签名并存。
- [ ] 验签：摘要、证书链、时间戳、DocMDP。
- [ ] 签名面板与状态展示（有效/警告/无效/未知）。
- [ ] RFC 3161 时间戳客户端（WinHTTP + TSQ/TSR 解析）。
- [ ] 验收脚本 `scripts/verify-signature.ps1`。

## 验收标准

- [ ] 签名后的文件在福昕与 Acrobat 中显示"签名有效"。
- [ ] 对已签文件追加任意内容后，本程序与福昕都报"签名后已修改"。
- [ ] 篡改已签字节后验签失败（负例守卫必须变红）。
- [ ] 二次签名（多人会签）后两个签名都有效。
- [ ] 手写签章外观在三个阅读器中位置与笔画一致。
- [ ] TSA 不可达时签名仍成功，并标注"无时间戳"。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 证书：自签名证书、过期证书、链不完整、智能卡（人工）。
- 结构：已有签名的文件再签、签署后保存、签署后打印、签署后加批注。
- 时间戳：正常 TSA、超时、返回错误、证书链不可信。

## 安全与隐私

- 私钥永不出证书存储；本程序不导出、不缓存私钥。
- 时间戳请求会暴露文档摘要与网络地址：默认关闭，首次启用需明确说明并记录审计。
- 验签结果不允许"乐观降级"：无法验证就显示未知，不显示有效。

## 依赖与许可证

- 使用 Windows CNG / CryptoAPI（系统组件），无新增第三方。
- 若后续支持跨平台签名，再评估 OpenSSL（Apache-2.0）并单独走一次依赖评审。

## 风险与回滚

- 风险：增量写入与占位符计算错误导致文件损坏或签名恒失效；智能卡驱动差异。
- 回滚：签名是"另存为"操作，原文件不动；恢复至 `v1.6.0`。
