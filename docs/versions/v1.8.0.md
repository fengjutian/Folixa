# v1.8.0 — 文档组装与批量

**状态：** Planned  
**唯一主要任务：** 支持页面提取、拆分、合并、替换、裁剪、水印与批量处理（对标项 D2–D9、B3、B8）。  
**前置版本：** v1.7.0

## 用户价值

用户可以把几十个 PDF 合成一本、把一本拆成几份、把某几页抽出来单独发、给整批文件统一加水印和页码，而不用一个个手工操作。

## 范围

### 范围内

- 提取与插入：从其他文件插入页面、抽取页面为新文档。
- 拆分：每 N 页、按顶层书签、按文件大小。
- 合并：多文件、书签合并、页面标签重映射、表单域重命名。
- 替换页、裁剪（CropBox 交互）、页框缩放。
- 书签：新建、改名、排序、删除、绑定目标。
- 页面标签与编号。
- 水印、页眉页脚、页码、背景。
- 批量：多文件任务（水印/页眉页脚/压缩/加密/导出图片），JSON 任务文件 + JSON 报告，可无界面运行（`--batch`）。

### 范围外

- 拼版印刷、出血、装订。
- 跨文档的自动目录生成（2.x 评估）。

## 设计决策

### 合并的正确性在"名字不冲突"，不在"页能拼上"

合并最容易被忽略的是副作用：表单域同名、书签目标失效、`/NM` 批注标识重复、页面标签错乱、目标名（`/Names`）冲突。合并器必须有一个**重命名阶段**：表单域加文件前缀、批注 `/NM` 加随机后缀、书签重建为新树（每份文件一个顶层节点）。

"页拼上了"只是第一步，能不能继续编辑、能不能正确跳转，全在重命名和重建这一步。

### 页面标签是独立于页序号的一层

文档可以有 `i, ii, iii, 1, 2, 3` 这样的标签序列，界面上的"第 N 页"和文件里的标签不是一回事。所有涉及页码的界面（跳转、打印范围、批注列表）都要区分 `pageIndex` 与 `pageLabel`，不能混用。

### 批量模式必须能脱离界面运行

批处理的价值在于脚本化和无人值守。所以：`AiPdfEditor.exe --batch job.json --report out.json`，退出码区分成功/部分失败/失败，报告逐文件列出动作与结果。界面只是这个能力的薄封装。

### 水印是内容流前置，不是注释

水印如果做成注释，别人删掉就没了；做成背景/前景的内容流（`ExtGState` 透明度 + 旋转矩阵），才是文档的一部分。这也意味着水印只能由写入层做。

## 实施步骤

- [ ] 页面操作扩展：插入/提取/替换/裁剪/页框。
- [ ] 合并器：页序、书签树重建、标签重映射、名称冲突处理。
- [ ] 拆分器：三种策略与命名规则。
- [ ] 书签编辑器（树操作 + 落盘）。
- [ ] 页面标签编辑。
- [ ] 水印/页眉页脚/页码/背景生成器。

- [ ] 验收脚本 `scripts/verify-assembly.ps1` 与 `scripts/verify-batch.ps1`。

## 验收标准

- [ ] 合并 20 个文件后页数正确，顶层书签每份一个节点且可跳转。
- [ ] 合并后同名表单域可分别填写，值互不干扰。
- [ ] 三种拆分策略产物页数正确，命名可预期。
- [ ] 裁剪后渲染区域与设定一致，旋转页不跑偏。
- [ ] 页面标签在跳转框与打印范围中正确显示。
- [ ] 水印在三个阅读器中可见，位置与透明度一致。
- [ ] 批量跑 100 个文件成功，失败项在报告中带原因，退出码正确。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 合并：带表单、带批注、带签名、带标签、不同页面尺寸、加密文件（应拒绝并提示）。
- 拆分：1 页文件、无书签文件、书签深度 >3。
- 批量：路径含中文与空格、只读目录、磁盘满、任务文件语法错误。

## 安全与隐私

- 批量模式不读取任务文件以外的任何路径；报告中不写文档内容，只写路径与结果。
- 合并加密文件需先解密（1.6.0 能力），无密码时跳过并记录，不静默失败。

## 依赖与许可证

- 使用 qpdf 的页面与对象操作，无新增第三方。

## 风险与回滚

- 风险：合并/拆分的重映射逻辑出错导致跳转错页或表单串值。
- 回滚：所有操作都是"另存为"，原文件不动；恢复至 `v1.7.0`。
