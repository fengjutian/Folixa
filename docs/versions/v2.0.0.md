# v2.0.0 — 超越福昕

**状态：** Planned  
**唯一主要任务：** 按对标基线完成收敛，达到"超过福昕"的判定条件并正式发布 2.0。  
**前置版本：** v1.11.0

## 用户价值

用户得到一个**比福昕更快、更小、更私密**的 PDF 工作台：同样的阅读、批注、表单、签名、编辑能力，启动快一个数量级，安装包小两个数量级，AI 能力可离线核验、可撤销、可审计。

## 范围

### 范围内

- 性能预算达成与回归门禁。
- 1000 份兼容性语料与崩溃率归零。
- AI 编辑闭环：自然语言 → 命令 diff → 逐条确认 → 执行 → 交叉核验。
- 文档比较（结构化差异 + 引用定位）。
- 评分卡审计：64 项 Must 全绿，7 项翻盘点至少 5 项成立。
- OCR 语言包缺失检测与安装引导（对标 I3）。
- 代码签名安装包、更新通道、发布说明。

### 范围外

- 企业 DMS 连接器、插件 SDK、云协作、移动端（基线 1.2 已明确不追）。
- PAdES-LTV、PDF/UA 生成。
- 本地大模型（2.x 评估）。

## 设计决策

### 性能预算写死，进 CI

| 指标 | 预算 | 测法 |
|---|---|---|
| 冷启动到可交互 | <0.8s | 10 次中位数，Windows 11 参考机 |
| 500 页首屏 | <300ms | 打开到首屏可滚动 |
| 滚动帧率 | ≥55fps | 帧时间采样，连续翻 20 页 |
| 1 GB 文件 | 可开、可翻、可搜 | 大文件语料 |
| 500 页峰值内存 | <400MB | 进程 RSS |
| 安装包 | <80MB | 产物字节数 |

预算不是"目标"，是**发布门禁**：任一项超标，2.0 不发。这也是"超过福昕"唯一可被外部验证的部分——功能和它对齐，速度和体积必须赢。

### AI 编辑的价值不在"能改"，在"改得可验证"

自然语言编辑最容易翻车的地方是"模型说改了，其实没改对"。闭环必须有三步：

1. **预演**：模型只输出结构化命令（`ReplaceText(page, rect, old, new)`），界面显示 diff，用户逐条确认；
2. **执行**：命令走 v1.11.0 的编辑引擎，进撤销栈；
3. **核验**：改完重新抽取该区域文本，与意图比对；不一致就标红并回滚该条。

第 3 步是福昕没有的，也是这个产品区别于"套壳聊天框"的地方。

### 文档比较要有引用，不只是红绿 diff

福昕的比较给出视觉差异。我们的比较要额外回答"这处差异在原文哪一段、改了什么"，并且**每条差异可点击跳转并高亮原文**。这直接复用了 0.11.0 的分块索引与引用核验——同一个底座，换一个使用场景。

### 发布即证据

2.0 的发布材料不是"我们做了很多功能"，而是可核对的证据包：评分卡逐项状态、性能测试原始数据、兼容语料通过率、翻盘点的度量截图、CI 全绿记录。

## 实施步骤

- [ ] 性能剖析与优化（启动路径、首屏渲染、内存回收）。
- [ ] 兼容语料建设（1000 份，含畸形与边缘样本），接入 CI 抽样回归。
- [ ] AI 编辑命令协议与 diff 预演界面。
- [ ] 编辑后交叉核验与自动回滚。
- [ ] 文档比较：结构差异、引用定位、报告导出。
- [ ] 评分卡审计脚本（把 64 项 Must 变成可执行检查表）。
- [ ] 安装包签名、更新通道、发布说明与隐私说明。
- [ ] 全量回归 + 72 小时稳定性。

## 验收标准

- [ ] 64 项 Must 全部达到"对齐"或"超越"，审计脚本输出逐项证据。
- [ ] 7 项翻盘点至少 5 项成立，且每项有度量数据。
- [ ] 六项性能预算全部达标，回归门禁接入 CI。
- [ ] 1000 份语料零崩溃、零"打开后白屏"。
- [ ] AI 编辑：错误命令必须被核验拦下并回滚（负例守卫）。
- [ ] 文档比较的每条差异可跳转定位。
- [ ] 安装包已签名，干净机器安装/升级/卸载通过。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 性能：冷启动、超大文件、极端缩放、连续翻页、长时间运行内存曲线。
- 兼容：1000 份语料全量 + 畸形文件模糊测试。
- AI：编辑命令的正确性、越权命令拒绝、核验失败回滚。
- 发布：签名校验、升级路径、卸载残留。

## 安全与隐私

- 威胁模型复核；依赖漏洞扫描；敏感日志审计。
- 2.0 发布前必须完成一次第三方安全评审（可委托外部）。

## 依赖与许可证

- 汇总全部第三方依赖的版本、来源、许可证与哈希，SBOM 与许可证清单必须一致。

## 风险与回滚

- 风险：性能预算达不到（尤其冷启动）导致 2.0 长期无法发布；签名证书采购周期。
- 回滚：保留 1.11.0 为最后一个功能版本；性能不达标时降级发布 1.12.0（功能完整但保留 1.x 版本号），**不用"2.0"这个名字掩盖没达标**。
