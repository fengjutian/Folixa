# v0.4.0 — 连续页面与瓦片渲染

**状态：** In Progress  
**唯一主要任务：** 实现支持长文档流畅浏览的连续页面视口和可取消瓦片渲染。  
**前置版本：** v0.3.0

## 用户价值

用户可以连续滚动、缩放并浏览多页 PDF，而不会因整本渲染造成明显卡顿或内存失控。

## 范围

- 当前视口瓦片渲染、邻页预取和 LRU 缓存。
- 缩放、旋转、适合宽度及适合页面。
- 渲染优先级、取消和内存上限。
- 范围外：文本选择、搜索和编辑。

## 设计决策

- **瓦片粒度是「页」，不是「页内切块」。** 本版的瓦片单位是一整页：
  视口内可见的页按需渲染，不可见的页不渲染。
  页内切块（把一页切成多块、按需绘制）能进一步减少首帧开销，
  但要为每个页面维护瓦片坐标系与边界裁剪，复杂度明显更高，
  留待后续版本。
- **渲染放在单独的线程上，PDFium 句柄不能跨线程用。**
  PDFium 的 `FPDF_DOCUMENT` / `FPDF_PAGE` 句柄只能在创建它的线程里使用，
  因此渲染线程自己持有一份独立句柄（`PdfDocument::isolatedCopy()`），
  文件字节用 QByteArray 隐式共享，不复制内存。
  主线程只负责布局、绘制和缓存，不碰 PDFium。
- **任务按「代」取消，不排队。** 每次滚动都会推进一个代号，
  渲染线程只处理最新一代的请求，旧的直接丢弃：
  快速滚动时待处理任务数不会无限增长。
- **缓存按像素字节计量上限。** LRU 淘汰的依据是 QImage 占用的字节数
  （宽 × 高 × 4），不是条目数，避免大图把内存吃穿。

### 本轮修掉的问题

1. **PDFium 渲染时不会自动应用页面的 `/Rotate`。**
   v0.3.0 显示旋转页时是**没转的**——当时验收只查了页码，没看方向。
   现在渲染时把「页面自带旋转 + 用户额外旋转」一起传给 PDFium，
   并新增 `displayWidthPoints()` / `displayHeightPoints()` 给出应用旋转后的显示尺寸。
2. **标签宽度会引发滚动位置漂移。**
   性能指标原先放在工具栏里，文字宽度一变，工具栏的溢出状态就变，
   画布高度跟着变，滚动范围又跟着变，当前滚动位置被 Qt 夹回去——
   于是「滚到底」只到第 481 页。
   现在指标移到状态栏常驻区，且滚动范围只在内容高度或视口高度真的变了时才重设。
3. **主程序被强杀后，AI worker 会变成永久孤儿进程。**
   验收脚本用 `Kill()` 强杀主程序时，`QProcess` 的析构函数不会执行，
   `WorkerClient` 来不及 terminate/kill，worker 就继续跑下去，
   既占内存，又锁住 `PdfAiWorker.exe`，让后续构建链接直接失败：
   `cannot open output file bin\PdfAiWorker.exe: Permission denied`。
   本机一度累积了 52 个孤儿 worker——这正是本轮流水线第一次失败的原因。
   现在 worker 启动时接收 `--parent-pid` 与 `--parent-start-time`，
   每秒检查父进程句柄是否还有效，父进程一消失就自行退出；
   创建时间用于识别 PID 复用，避免跟错进程。
   验收脚本另外加了孤儿清理作为兜底。
4. **密码对话框的 UIA 元素会在写入前失效，异常直接打断整条流水线。**
   Qt 在重建控件时会释放对应的 UIA provider，
   `SetValue` 于是抛 `ElementNotAvailableException`；
   这个异常没有被捕获，一处抖动就让整个验收脚本退出。
   现在密码流程按次重试：每次重新取对话框和输入框，
   控件读取也逐元素容错（状态栏标签每 100ms 刷新一次，
   随时可能把某个元素变成失效状态）。
   异常只让对应场景判失败，不再打断整条流水线。

### 已知问题

1. 瓦片粒度是「页」，不是「页内切块」；页内切块能进一步减少首帧开销。
2. 页面缓存只缓存整页图像，没有做跨页的共享资源（如字体、位图）复用。
3. 缩放时不做增量重绘，整页重渲染；高倍率下大文档的缩放响应偏慢。
