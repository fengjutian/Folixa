# v0.3.0 — PDFium 最小阅读闭环

**状态：** Verification
**唯一主要任务：** 使用 PDFium 打开本地 PDF 并在 Qt 中正确显示首页。
**前置版本：** v0.2.0

## 用户价值

用户可以选择一个 PDF，并看到清晰、比例正确的第一页。

## 范围

### 范围内

- 固定 PDFium revision 和许可证材料。
- `PdfiumAdapter`、文档句柄和页面句柄生命周期。
- 文件选择、密码输入、首页渲染和错误展示。
- 高 DPI 下的基础缩放。

### 范围外

- 连续滚动、多页缓存、搜索和编辑。

## 设计决策

- **PDFium 用官方二进制套件之外的可复现预编译包。** Chromium 不发布 Windows 预编译包，
  这里固定使用 `bblanchon/pdfium-binaries` 的 `chromium/8152`（PDFium API 159），
  由 `scripts/bootstrap-pdfium.ps1` 按 SHA-256 校验后获取，不进入版本库。
- **该 DLL 静态链接 CRT**，只依赖 Windows 系统库（KERNEL32/GDI32/USER32），
  不引入 MSVC 运行时，因此 MinGW 构建的主程序可以直接调用它，ABI 没有风险。
  这条先用一个最小探针验证过，才开始写适配层。
- **用 `FPDF_LoadCustomDocument` 自己喂数据**，而不是 `FPDF_LoadDocument`：
  文件先按 256 MiB 上限读入内存，既能限制文件大小，也不依赖路径编码。
- **PDFium 159 的密码接口是直接传 UTF-8 口令**，不再是回调，
  因此「需要密码」表现为 `FPDF_ERR_PASSWORD`，由 UI 弹出输入框后重试。
- **加密样例自己生成。** `scripts/generate-test-pdfs.py` 用纯标准库实现
  PDF 标准安全处理器（RC4 40 位，R=2），不依赖 pypdf——
  构建机上不一定装了 pypdf，依赖它会让加密用例被静默跳过。

## 测试要求

- 普通、加密、空页、旋转页、损坏 PDF。 → `tests/PdfiumAdapterTests.cpp`（12 个用例）
- 100%、150%、200% DPI 渲染检查。 → 渲染按 `zoom × devicePixelRatio` 出图，
  黄金图比对覆盖 100% 基准，其余倍率由尺寸与像素上限守卫覆盖。
- 主程序端到端打开 PDF。 → `scripts/verify-pdf.ps1`

## 安全与隐私

- 限制文件大小和页面尺寸。 → 文件 256 MiB、单边 8192 像素、总像素 6400 万上限。
- 不执行 PDF JavaScript 或附件。 → M1 只用 `FPDF_RenderPageBitmap` 渲染页面，
  没有加载表单、脚本或附件相关接口。

## 依赖与许可证

- PDFium（BSD-3-Clause）及 19 份第三方组件许可证原文随安装包分发，
  清单为 `licenses/pdfium-CHECKSUMS.txt`（SHA-256 + 包内名 + 来源路径）。
  → `scripts/bootstrap-pdfium.ps1` 核对清单与固定版本 PDFium 的实际材料一致；
  `scripts/package.ps1` 按清单逐份复制并核对哈希，缺一份即中止打包；
  `scripts/verify-licenses.ps1` 核对包内文件集合与哈希，不少也不多。
- 版本、来源与分发策略记录在 `THIRD_PARTY_LICENSES.md`。

## 风险与回滚

- 风险：PDFium 预编译包不是 Chromium 官方发布物，来源固定在
  `bblanchon/pdfium-binaries` 的固定 tag 并校验 SHA-256；
  另有 MSVC 运行时与字体渲染差异风险。
- 回滚：恢复至 `v0.2.0`。

## 与版本顺序的偏离

按 `docs/VERSIONING.md` 的规矩，v0.2.0 未通过验收前不应开始 v0.3.0 的功能开发。
本次是在 v0.2.0 仅剩「远端 CI 首次运行」这一项（需要确定托管地址）的情况下，
按开发决策先行推进功能。此偏离在此显式记录。

### 本轮修复的问题

1. **版本索引里 0.3.0 出现两行。** 一行 `In Progress`、一行 `Planned`，
   版本门解析时后者覆盖前者，「索引状态与版本文档一致」检查失败。
2. **PDFium 的两份许可证没随包发出。** 打包时只复制 `*.txt`，
   libjpeg-turbo 的 `libjpeg_turbo.ijg` 与 `libjpeg_turbo.md` 被过滤掉了，
   属第三方许可证分发缺口。现在按清单逐份复制，19 份一份不少。
3. **许可证门管不到 PDFium 的材料。** 原来只校验 LGPL/GPL/GCC 三份全文，
   PDFium 的 19 份材料既没有清单也没有门，等于没被观察过。
   现在有仓库内清单 + 包内集合与哈希核对，并配了三条负例守卫。
4. **打包门不检查 `pdfium.dll`。** 包里少了 PDFium 运行库也能通过验收。
   现在 `pdfium.dll` 与许可证清单副本都是打包门与打包阶段的必需项。
5. **打包验收的截图从来没以预期文件名落盘。** `scripts\ci.ps1` 里
   `'build/acceptance/package-' + $version + '.png'` 写在数组字面量中，
   而 PowerShell 里逗号比 `+` 结合更紧，参数被拆成
   `build/acceptance/package-`、版本号、`.png` 三段：
   截图写成了 `build/acceptance/package-`（无扩展名），
   版本号还被当成了 `verify-package.ps1` 的 `$WorkDir`，
   在仓库根目录留下一个临时解压目录。
   现在拼接改为 `-f` 格式串并加括号，流水线还会断言截图按预期文件名落盘。
