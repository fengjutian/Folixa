# v0.6.0 — 缩略图、书签、链接与页面导航

**状态：** Released  
**唯一主要任务：** 让用户看得见文档全貌、跳得到任何位置、点得动页面里的链接。  
**前置版本：** v0.5.0
**发布标签：** `v0.6.0`

## 用户价值

打开长文档后，用户能立刻看到每一页的缩略图，并沿着文档自带的大纲、书签或页面里的
链接直接跳到想看的位置，不必靠滚动去找。

## 范围

### 范围内

- 读取 PDF 大纲（PDF 规范里也叫书签），以分层树展示，点击跳到对应页。
- 大纲同时提供扁平列表视图，填满导航栏的「书签」页签。
- 读取页面上的链接注释：内部链接跳到目标页，外部链接交给系统浏览器打开。
- 链接区域的鼠标指针变化，提示可点。
- 缩略图导航：点击缩略图跳到该页，并高亮当前页。

### 范围外

- 用户自定义书签的增删改与持久化（本版本只读文档自带的大纲）。
- OCR 与语义搜索。
- 跨文档的全局导航与历史记录。

## 设计决策

- **主线程不碰 PDFium，大纲与链接都由后台线程提取。**
  PDFium 的文档句柄不能跨线程共享，v0.5.0 已经把页面几何改成随文本层一起回传，
  本版本沿用同一套办法：后台线程在已有页面句柄上顺手把大纲和该页链接取出来，
  主线程只拿纯数据。
- **大纲的树结构在适配层构建，UI 只负责展示。**
  这样标题、层级、目标页码的解析规则可以被单元测试直接覆盖，
  不必拉起界面。
- **链接命中用矩形相交判定，不用 PDFium 的 `FPDFLink_GetLinkAtPoint`。**
  那个接口需要页面句柄，等于把 PDFium 拉回主线程；
  后台线程已经把每页链接矩形取回来，主线程做纯几何判定即可。
  同一点命中多个链接时取**枚举顺序靠后**的那个（PDFium 按 Z 序枚举，越靠后越在上层）。
- **外部链接交给系统浏览器**（`QDesktopServices`），与常见阅读器一致：
  用户点击本身就是授权，本应用不主动联网。
- **只读大纲，不做用户书签。**
  用户书签要牵涉持久化与冲突处理，属于另一个版本的范围，不在这里静默扩大。
- **书签页签与目录页签同源。**
  PDF 规范里「书签」就是大纲的另一个叫法，两者是同一份数据：
  目录页签给分层树，书签页签给扁平列表（用缩进表示层级）。
  不额外造一份「用户书签」数据结构，避免两边不同步。
- **PDFium 的书签目标有两个来源，必须都读。**
  `FPDFBookmark_GetAction` 只在条目带 `/A` 动作时有值；
  只写 `/Dest` 的条目必须回落到 `FPDFBookmark_GetDest`，
  否则一大半书签会显示成「没有目标」。
- **外部链接的地址要去掉结尾的 NUL。**
  `FPDFAction_GetURIPath` 的返回值**含结尾的 NUL**（PDFium 文档明写），
  不裁掉的话地址末尾会挂一个不可见字符，界面上看不出来但链接打不开。

## 测试要求

- 大纲解析：多层嵌套、目标页码、`/Dest` 与 `/A` 两种写法、UTF-16 中文标题、
  没有大纲的文档。
- 链接提取：内部跳转的目标页、外部 URI、按页隔离、重叠链接的枚举顺序。
- 链接命中：矩形相交、不相交、多个命中时取 Z 序最上层、退化矩形、
  页面自带 `/Rotate` 与用户旋转下的坐标换算。
- 端到端：`scripts/verify-navigation.ps1` 走真实界面——点目录、点书签、
  点内部链接跳页、点外部链接、点重叠链接验证上层胜出、点空白处不误触发、
  没有大纲的文档显示空状态。
- 夹具：`navigation.pdf`（多层大纲 + 三种链接 + 无链接页，标题为 UTF-16 中文）。

### 验收脚本的取舍

- 外部链接在验收里用 `AIPDF_SUPPRESS_EXTERNAL_LINKS=1` 抑制真的拉起浏览器：
  验收跑在 CI 上，拉起浏览器会打断脚本。被断言的是「点击被识别成外部链接
  并拿到了正确地址」，真正调用系统浏览器只是最后一行系统调用。
- 面板内容不进 UIA 文本（`QStackedWidget` 只暴露当前页），
  条目数由应用写进轨迹文件（`panel outline items=N` / `panel bookmarks items=N`），
  脚本据此断言面板里真的有内容，而不是只断言「没报错」。

## 安全与隐私

- 大纲、链接信息只保存在内存里，不落盘、不外发。
- 外部链接由用户点击触发，交给系统浏览器打开；本应用不主动发起网络请求。
- 新增的 PDFium 调用全部走进程级递归互斥量（与 v0.5.0 同一把锁）。

## 依赖与许可证

- 无新增依赖，无许可证变化。

## 风险与回滚

- 风险：畸形文档的大纲可能存在环形引用，PDFium 明确要求调用方处理。
  → 提取时限制深度与条目总数，超限即停止并保留已取到的部分。
- 风险：链接注释可能指向不存在的页或损坏的目标。
  → 目标页越界时忽略该链接，不崩溃、不跳转。
- 回滚：恢复至 `v0.5.0`。

### 过程中被测试抓出来的缺陷

- **书签目标只写 `/Dest` 时解析不出来。** PDFium 的 `FPDFBookmark_GetAction`
  只在条目带 `/A` 动作时有值，PDFium 文档要求此时改调 `FPDFBookmark_GetDest`。
  只看动作会漏掉一大半书签——单元测试里两个顶层条目里有一个就是这种写法。
- **外部链接地址末尾多一个 NUL。** `FPDFAction_GetURIPath` 的返回值含结尾 NUL
  （PDFium 文档明写），不裁掉的话地址是错的，链接打不开；界面上看不出来。
- **目录树的子条目默认收起**，用户一眼看不到层级；验收脚本也点不到收起的条目。
- **悬停手型光标需要鼠标跟踪**，画布视口原来没开，链接热区没有手型提示。

### 已知限制

- 缩略图列表只渲染前 24 页，因此「高亮当前页」只对这 24 页有效
  （与缩略图列表本身的既有行为一致）。
- 「用户自定义书签的增删改与持久化」按约定在本版本范围外。
- 外部链接在验收中不真的拉起浏览器（`AIPDF_SUPPRESS_EXTERNAL_LINKS=1`）：
  CI 上拉起浏览器会打断脚本。被断言的是「点击被识别成外部链接并拿到了正确地址」。
