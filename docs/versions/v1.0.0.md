# v1.0.0 — 首个正式版本（Windows x64 便携版）

**状态：** Released
**发布标签：** `v1.0.0`
**唯一主要任务：** 把 `v0.15.0` 之后已经落地并验收的能力整体收口为首个正式版本，
结束「代码已实现、版本文档仍是 Planned」的错位。
**前置版本：** v0.15.0

## 用户价值

用户拿到的是一个可以直接解压运行的 Windows x64 正式版：阅读、检索、批注、表单、加密与权限、
签名与验签、页面组装、格式转换、无障碍与内容编辑都在同一个包里，版本号、
文档、安装包与 SBOM 对得上。

## 范围

### 范围内

- 收口 `v0.15.0` 之后落地的 1.1–1.11 能力：阅读布局与放映、打印与导出、PDF 写入层与批注外观流、
  批注互操作、AcroForm 与静态 XFA、加密/权限/遮盖、数字签名与验签、页面组装与书签、
  格式转换与 PDF/A 预检、国际化与无障碍、文本/图像/对象内容编辑。
- 冻结依赖与工具链；Debug/Release 构建、全量单元与集成测试、打包与发布门。
- 产出便携 ZIP、SBOM、第三方许可证全文、SHA-256 与发布说明。
- 版本号统一到 `1.0.0`；版本索引与 1.1–1.11 文档状态回填为 `Delivered`。

### 范围外 / 明确推迟

- **MSI/EXE 安装器、代码签名证书、自动更新通道**：推迟到后续发布工程版本
  （[v2.0.0](v2.0.0.md) 仍把它们列为要求）。本版本交付的是便携 ZIP。
- **72 小时连续稳定性**：没有在独立机器上执行，写入已知限制，不宣称完成。
- **1.1–1.11 不单独发版**：能力随 `v1.0.0` 交付，文档状态记 `Delivered`，不建独立标签。
- 企业 DMS 连接器、插件 SDK、云协作、移动端：产品基线已明确不追。

## 设计决策

### 为什么用 1.0.0 一次收口，而不是逐个发 1.1–1.11

代码事实已经不支持逐个补标签：矩阵 276 条命令里 missing 为 0，评分卡 102 项里未做与欠账都为 0。
1.1–1.11 的主体能力早已落在同一个代码基线上，逐个发版只会产生 11 个指向同一提交、
没有独立历史的空标签。用 `1.0.0` 作为首个正式版收口，版本号才代表用户真正拿到的产品。

### 为什么 1.1–1.11 标 `Delivered` 而不是 `Released`

`Released` 在 [版本规范](../VERSIONING.md) 里的定义是「满足发布条件并建立 Git 标签」；
这些版本号没有独立标签，标 `Released` 会制造假历史。`Delivered` 的含义是
「能力已随另一个发布版本交付」，既不丢失交付事实，也不伪造标签。

### 为什么不把安装器塞进 1.0.0

安装器需要签名证书、升级/卸载路径与干净机器验证，这三件事都不是本机当前能闭环的。
把它们写进 1.0.0 的验收再标 Released，等于用一句「已完成」掩盖四个没做的门；
所以本版本明确交付便携 ZIP，把安装器/签名/更新通道作为后续版本的唯一主要任务。

### 发布证据必须可重跑

版本号、构建、测试、打包与文档一致性全部由脚本门禁检查，不靠人工勾选：
`check-version.ps1` 对 CMake、vcpkg、版本文档、索引、exe 与包名；
`check-docs-consistency.py` 对矩阵、评分卡与审计数字；
`verify-package.ps1` 在无 Qt SDK 的 PATH 下启动包内主程序。

### 发布过程中修掉的缺陷

- **Qlementine 1.4.2 的 `QComboBox` 事件过滤器无限递归**：`ComboboxItemViewFilter`
  在 `ChildAdded` 里调用 `_comboBox->view()`，而 `view()` 会创建弹出容器并再次触发
  `ChildAdded`；Release 包一构造 `QComboBox` 就栈溢出（`0xC00000FD`），打包验收
  因此四项全红。已加补丁 `cmake/patches/qlementine-1.4.2-combobox-recursion.patch`
  （把 `_comboBox->view()` 换成过滤器已持有的 `_view`），由
  `cmake/apply-qlementine-patch.cmake` 在 CMake FetchContent 阶段幂等应用；
  Release 主程序窗口正常出现，`verify-package.ps1` 六项启动检查全部通过。
- **`TextSplice` 的回退字体指针在 Release 下悬空**：`scanFonts.fonts.append(decoded)` 会触发
  `QVector` 扩容，把 `ShowSpan::font` 指向的旧元素搬走；Release 下 `FontResource::encode`
  直接读已释放内存，`TextSpliceTests` 在第 8 个用例段错误（Debug 只是碰巧没触发）。
  已改成追加前 `reserve(size + 1)`，并用完整 Release 测试套件复验。
- **`RoleInference.cpp` 用 `QLatin1Char('。')` 判中文句号**：`QLatin1Char` 只收单字节，
  多字符字面量被截断，中文句号/分号结尾的句子永远不会被判成「不是标题」。
  结果是字号稍大的正文句子可能被误打成 H1。已改成 `QChar(0x3002)` / `QChar(0xFF1B)`，
  并在 `SemanticTagWriterTests::roleInferenceFindsHeadingParagraphAndList` 里加了
  「中文句号结尾的 18pt 句子必须是段落」的断言（退回旧实现该断言当场变红）。
- **`check-version.ps1` / `verify-dependencies.ps1` / `verify-navigation.ps1` 缺 UTF-8 BOM**：
  `ci.ps1` 的脚本编码自检会直接拦住整条流水线；已补 BOM，并用 PowerShell 5.1 实跑
  `check-version.ps1` 通过。
- **两个朗读稿脚本在 GBK 控制台会抛 `UnicodeEncodeError`**：门禁变红会被伪装成脚本崩溃；
  已显式把 stdout/stderr 重设为 UTF-8（`errors=replace`），负例对照实跑通过。

### 已知限制

- **没有安装器、代码签名与自动更新通道**：交付物是便携 ZIP；企业分发与升级路径未验证。
- **72 小时连续稳定性未执行**：需要独立且不被打断的机器，本版本没有给出可信数据。
- **界面验收未在本机重跑**：`verify-*.ps1` 会抢占前台，按仓库约定留给 CI；
  本版本不把「没跑」写成「通过」。
- **8 条命令仍是 partial**：高级打印、PDF 优化、扫描仪（2 行）、OFD 批量（2 行）、
  OneNote、AI 面板；边界见功能矩阵说明列。
- **外部验证缺口**：Ghostscript、veraPDF、真机扫描仪、OneNote COM 与读屏软件
  仍未在本机完成真机验证。
