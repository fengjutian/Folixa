# v1.5.0 — 表单

**状态：** Planned  
**唯一主要任务：** 支持 AcroForm 表单的显示、填写、保存与扁平化（对标项 F1–F6）。  
**前置版本：** v1.4.0

## 用户价值

用户可以填写报税表、申请表、合同附件这类交互式 PDF，填完保存或扁平化后发给别人，对方看到的和填的人看到的一致。

## 范围

### 范围内

- 表单渲染与交互：文本框、复选框、单选组、下拉框、列表框、按钮、签名域占位。
- 键盘操作：Tab 顺序、输入、退格、复制粘贴、焦点环。
- 字段属性：只读、必填、最大长度、格式（数字/日期/货币）。
- 计算与校验脚本的**白名单子集**（`AFSimple_Calculate`、`AFNumber_Format`、`AFRange_Validate` 等）。
- 保存填写值；扁平化（把外观烧进页面内容，删除控件）。
- 数据导入导出：FDF / XFDF / CSV。

### 范围外

- 表单设计器（新建域、改域属性）：对标项 F5 明确不做。
- XFA 动态表单：PDFium 没有 XFA 引擎，**必须显式提示"本文件为 XFA 表单，暂不支持"**，不许显示成空白页。
- 完整的 JavaScript 引擎。

## 设计决策

### 用 PDFium 的表单环境，不自己实现控件

PDFium 有完整的表单交互层（`FPDFDOC_InitFormFillEnvironment` + `FPDF_FFLDraw` + `FORM_OnLButtonDown/OnChar/OnKeyDown` 等事件）。自己实现等于重写一遍焦点、选择、滚动、外观逻辑，且必然与别的阅读器不一致。

做法：`PdfPage::render()` 在表单模式下改为 `FPDF_FFLDraw`，Qt 的鼠标键盘事件翻译成 PDFium 事件结构转发。**控件外观由 PDFium 画，值由 PDFium 存**，我们只做事件搬运与界面适配。

### 计算脚本：先白名单，再考虑引擎

预编译的 PDFium 不一定开了 V8。若没有 V8，表单里的计算域就是死值。方案分两级：

1. 白名单：识别 `AFSimple_Calculate` / `AFNumber_*` 这类标准函数，用内置求值器算——覆盖绝大多数报税、报销、报价单；
2. 若构建的 PDFium 带 V8，则整体交给 PDFium，白名单自动失效。

判定时机在运行时（探测 `FPDF_GetFormType` 与 JS 能力标志），不在编译期，避免两套二进制。

### 扁平化必须走写入层

扁平化 = 把控件外观画进页面内容流 → 删除 widget 注释 → 清理域树。最后一步必须用 v1.3.0 的 `DocumentWriter`（需要删对象、改 `/AcroForm`），PDFium 做不到"删掉域但保留外观"。

### 保存值只改注释，不重建表单

填写值存在 widget 注释的 `/V` 里。保存走增量更新，只改这些注释对象——不重建页面、不动域树、不破坏已有签名以外的内容。

## 实施步骤

- [ ] 表单环境初始化与页面加载/卸载生命周期。
- [ ] `FPDF_FFLDraw` 渲染路径，替换纯页面渲染。
- [ ] 事件翻译层：鼠标、键盘、焦点、滚轮、Tab 顺序。
- [ ] 字段高亮、只读与必填提示。
- [ ] 白名单计算与格式化求值器。
- [ ] 保存填写值（增量更新）。
- [ ] 扁平化（外观烧入 + 删控件 + 清域树）。
- [ ] FDF/XFDF/CSV 导入导出。
- [ ] XFA 检测与明确提示。
- [ ] 验收脚本 `scripts/verify-forms.ps1`。

## 验收标准

- [ ] 10 类字段均可填写，Tab 顺序与福昕一致。
- [ ] 填写后保存，用福昕打开值不丢失、外观不变。
- [ ] 计算域（合计、税额）结果与福昕一致，误差为 0。
- [ ] 扁平化后文档不再含 widget 注释，任何阅读器都无法再编辑，像素与原外观一致。
- [ ] XFA 文件给出明确提示且不崩溃。
- [ ] FDF/XFDF/CSV 往返一致（值、字段名、页）。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 字段：同名单选组、跨页字段、只读域、隐藏域、多行文本、带掩码的日期。
- 异常：域树损坏、字段数与注释数不匹配、循环计算。
- 兼容：用福昕、Acrobat 分别填写同一份表单后由本程序读取。

## 安全与隐私

- 表单脚本只走白名单，**不执行任意 JavaScript**（不引入 JS 引擎就谈不上沙箱逃逸）。
- 导入的 FDF/XFDF 只按字段名匹配已有域，不许创建新域、不许带外链。

## 依赖与许可证

- 无新增第三方；若后续启用 V8，需重新评估 PDFium 构建产物与许可证。

## 风险与回滚

- 风险：PDFium 表单层与 Qt 事件循环的焦点/输入法交互容易出现"打不进去字"。
- 回滚：表单模式可整体关闭，退回只读渲染；恢复至 `v1.4.0`。
