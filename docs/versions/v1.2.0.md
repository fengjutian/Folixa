# v1.2.0 — 打印与输出

**状态：** Planned  
**唯一主要任务：** 让文档能被打出来、被导出成图片和文本（对标项 H1–H4）。  
**前置版本：** v1.1.0

## 用户价值

用户可以把 PDF 打印到纸或虚拟打印机，批注跟着一起出来；也可以把页面导出成图片发给别人，或导出成文本做检索。

## 范围

### 范围内

- 打印：页面范围、份数、纸张、方向、双面、边距、缩放（实际大小/适合/自定义）。
- 多页合一：2/4/6/9 页拼一张，带分隔线。
- 批注随打印输出；可选"仅打印文档"。
- 打印预览。
- 导出图片：PNG / JPEG / TIFF，72–600 DPI，页面范围。
- 导出文本：按阅读顺序，页间用换页符分隔，UTF-8 with BOM。

### 范围外

- 虚拟打印机驱动（需要驱动签名与内核组件）。
- 拼版印刷（imposition）、出血与装订标记。
- PDF→Office（1.9.0）。

## 设计决策

### 打印走"渲染成图"，不走系统 PDF 打印栈

系统打印栈会把 PDF 再解释一遍，结果和我们屏幕上看到的不一致（尤其是我们自己绘制的批注）。打印路径统一为：`PDFium 渲染页面位图 → QPainter 叠加批注 → QPainter 画到 QPrinter`。这样"屏幕上什么顺序、纸上就是什么顺序"，同一套绘制代码。

代价是高 DPI 打印的位图内存：A3/600DPI 单页约 100MB。对策是分带渲染（banding），每带限制在 64MB 以内。

### 批注打印与 v1.3.0 的外观流共用一套绘制器

现在批注是应用层自绘的（PDFium 不生成 /AP）。1.3.0 之后批注有了 /AP，PDFium 能自己渲染。为了不在 1.3.0 之后改两遍打印代码，绘制器从一开始就抽象成"输入批注列表与页面变换，输出 QPainter 指令"，1.3.0 之后只是把它换成"不再调用，直接信任 PDFium"。

### 导出文本按阅读顺序，不按内容流顺序

内容流顺序常常是乱序的（双栏、脚注、水印）。导出复用 v0.9.0 的 `ChunkBuilder` 排版排序，页内按块、块内按行。做不到完美，但比内容流顺序可读得多。

## 实施步骤

- [ ] 打印引擎：分带渲染、DPI/纸张/方向映射、页面范围与份数。
- [ ] 多页合一布局计算与分隔线。
- [ ] 批注绘制器抽象，打印路径接入。
- [ ] 打印预览（同一条渲染路径，低 DPI）。
- [ ] 图片导出：格式、DPI、范围、命名规则（`<文档名>-p<页码>.<ext>`）。
- [ ] 文本导出：阅读顺序排序、分页符、BOM。
- [ ] 验收脚本 `scripts/verify-print.ps1`（打印到 Microsoft Print to PDF 后回读）。

## 验收标准

- [ ] 打印到 PDF 后回读：页数、页面尺寸、方向与原文档一致。
- [ ] 带高亮/便签/方框的文档打印后，批注像素位置与屏幕一致（容差 ≤2px）。
- [ ] 2/4/6/9 合一的排布顺序正确（先左后右、先上后下）。
- [ ] 600 DPI A4 打印峰值内存 <512MB（分带生效）。
- [ ] 导出图片的像素尺寸 = 页面点数 × DPI / 72（误差 ≤1px）。
- [ ] 导出文本与界面抽取结果逐字一致，页序正确。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 打印：旋转页、非 A4 页面、超长页面、空白页、加密文档、取消打印。
- 导出：透明背景、灰度、CMYK 图片、超大页面（>200 英寸）。
- 文本：双栏、表格、竖排、OCR 页（无文本层时给出明确提示）。

## 安全与隐私

- 打印与导出不发起任何网络请求；临时文件写在系统临时目录并在完成后删除。
- "不允许打印"的加密文档必须遵守权限位（1.6.0 起生效，本版本先留判定接口）。

## 依赖与许可证

- 仅使用 Qt PrintSupport（LGPL-3.0，已在许可证清单内），无新增第三方。

## 风险与回滚

- 风险：高 DPI 位图导致内存暴涨或打印假死。
- 回滚：打印入口可整体隐藏；恢复至 `v1.1.0`。
