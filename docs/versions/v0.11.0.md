# v0.11.0 — 可验证文档问答

**状态：** In Progress  
**唯一主要任务：** 实现关键词与向量混合检索、引用验证及点击定位。  
**前置版本：** v0.10.0

## 用户价值

用户能针对整份文档提问，并通过页码和高亮原文核验答案。

## 范围

- Embedding Provider 抽象与一个**本地确定性**嵌入实现；向量索引与混合检索。
- 整篇问答的范围切换（当前页 / 整篇文档）与上下文构建。
- 引用协议、离线引用核验、点击引用跳到原文并高亮。
- IPC 协议升到 3：`ai.chat.stream` 的载荷多了 `context`（带编号的上下文块），任务类型多了 `qa`。
- 范围外：多文档知识库、自动编辑（v0.14.0）、云端嵌入模型（见「已知限制」）。

## 设计决策

### 对标：混合检索怎么融合、引用怎么验证

动手前查了同领域的成熟做法（Microsoft Learn / Azure Cosmos DB 的 RRF 检索、
Elasticsearch 的 RRF 检索器、LangChain 等 RAG 框架的 reciprocal rank fusion，
以及业界关于「引用核验」的讨论）：

| 做法 | 对标来源 | 本项目的取法 |
|---|---|---|
| 两路检索用 **RRF**（只用名次）融合 | Azure Cosmos DB RRF、Elasticsearch RRF | `doc::HybridRetriever`：两路各取名次，`Σ w/(60+rank)` |
| 融合**不按分数相加** | 同上 | 余弦在 -1..1、命中次数可以任意大，量纲不可比，相加会让混合退化成单路 |
| 引用核验：编号存在性 + **引文逐字核对** | 业界「引用可验证」实践 | `doc::CitationVerifier`：编号 / 逐字 / 页码三重检查 |
| 不做二次模型蕴含判断（entailment） | 成本与可靠性权衡 | 每次提问成本与延迟翻倍，小模型做蕴含本身就不可靠 |

### 嵌入先做本地确定性实现，不接云端嵌入模型

`ai::EmbeddingProvider` 是抽象（`embed` / `dimension` / `id` / `isDemo`），
v0.11.0 的实现是 `ai::LocalHashEmbedding`：哈希 n-gram 向量，256 维，L2 归一化。

理由是**整条链路必须能在离线状态下跑通**：引用核验是这一版的核心价值，
如果检索那半边依赖密钥与云端，验收就只能靠真金白银的调用跑，
而且换个网络环境结果就不一样了。本地实现同样文本永远给同样向量，
不联网、不花钱、结果可复现。换成云端嵌入模型时，只要实现同一个接口，上层一行不用改。

分词：拉丁按词，中文按「单字 + 相邻二字组」。中文没有空格，不切词整段就是一个词；
只取单字又太短（「自动保存」与「自动保存文档」分不出），二字组才是中文最小的有效语义单位。

它比纯关键词检索强在哪：n-gram 让「部分重合」也能得分。它比神经网络嵌入弱在哪：
不认识同义词（「费用」与「价格」互相无关）。所以它与关键词检索是**互补**的两路，
正好用 RRF 融合。

### 关键词那半边不用 FTS5

原计划写的是「FTS5 与向量结果融合」。实际没做，两个原因：

1. 本工具链下 `QSqlDatabase::addDatabase("QSQLITE")` 必崩（0xC0000374），
   引入 SQLite 等于引入一个跑不起来的依赖；
2. v0.9.0 的探针实测（`build/probe/fts_probe.py`）：一千段（每段 220 字）做一次
   子串扫描只要 0.1 ms——这个规模下倒排索引带来的复杂度换不来速度，
   而且子串匹配中文直接就能搜，不用分词。

所以关键词那半边复用 `doc::LocalIndex::search`（子串匹配，忽略大小写），
但**不拿整句去匹配**：用户问的是一句自然语言，整句在原文里永远匹配不到，
那一半检索就成了摆设，混合检索退化成单路向量检索。

改法是**按词元**检索：中文取二字组、拉丁取整词（复用嵌入实现的那套分词），
逐个词元检索后按「命中了几个**不同的**词元」排名。
单字（「的」「是」「在」）在中文里几乎每段都有，命中它没有区分度，直接丢掉。

### 引用核验完全离线、确定性

`doc::CitationVerifier` 做三项检查，全部是字符串核对，**不需要再调一次模型**：

1. **存在性**：引用的编号必须在这次给模型的上下文块里。凭空造编号 → 作废。
2. **引文核对**：模型引的那段原文必须真的出现在被引用的那一块里。
   编号对、引文是编的——这是最常见的一种伪造。
3. **页码一致**：模型写的页码必须与那一块的实际页码一致。不一致的话，
   用户点引用会跳到错误的页。

比对时忽略空白与全半角差异（`LocalHashEmbedding::normalize` 统一归一化）：
模型给引文换行或加空格不是「引文改了」，只是排版。

**判无效只把引用标成「无法核实」，不丢答案正文**：宁可让用户看见一条查不到出处的引用，
也不要把可能有用但没核过的内容一起删掉。

### 块 id 里没有页号，向量索引要另存映射

v0.9.0 的块 id 是「页内容指纹 + 页内块序号」（例如 `a1b2b0`），**不含页号**。
两页内容完全一样时按 id 全局取会拿到另一页的块——这个坑 v0.9.0 就踩过。

所以 `doc::VectorIndex` 额外存一份 `块 id → 页码`；取块一律走 `chunkByIdOnPage`，
定位到原文也走 `PdfView::showIndexedChunk(pageIndex, chunkId)`。

### 向量索引单独存

落在 `index/vectors/<sha1>.json`，与 `LocalIndex` 分开。两者重建节奏不同：
块随内容变，向量还随嵌入模型变。分开存，换嵌入模型时不必重切块。

存法是 JSON + 每个向量一段 base64 的 float32（**小端**）。不用二进制文件是因为：
JSON 能人眼检查、能被负例守卫改坏、能原子替换，而这个规模下体积优势不重要
（一千块约 1 MB）。字节序手工拆，不直接 `memcpy` 原始内存——
索引文件要长期保存，换台机器读出错字节序的症状是「检索结果莫名其妙」，极难查。

### 检索与核验在主程序，模型调用在 Worker

沿用 v0.10.0 的边界：主程序永远不碰网络与密钥。

- 主程序做混合检索、拼带编号的上下文、核验模型的回答；
- Worker 里的 Provider 调模型；
- 两边通过 IPC 传的是**已经拼好的提示词**与**结构化的上下文块**。

结构化的那份（`context` 数组）让演示模式能引用**真实的**块，而不是编一段像样的样子。

### 演示模式必须引用真实块

`MockProvider` 的问答回答，引文取块的第一行、逐字照抄、不加省略号。
这样引文一定能在原文里核对到，演示模式也能跑通完整的核验链路。

负例靠环境变量 `AIPDF_AI_MOCK_FAKE_CITATION`：演示模式据此故意引一句原文里没有的话，
验收脚本用它证明「引用核验真的在核对原文」，而不是永远显示「已核实」。

### 引用清单是真实控件，不是 HTML

回答正文里的 `[n]` 是行内链接（点一下跳到原文），下面另有一个 `QListWidget`
列出每条引用与它的核验结果（「[1] 第 1 页 · 已核实」）。

理由是引用是这个功能的**产物**：用户要能一眼看到每条引用核过没有、点哪一条跳哪一页。
用 HTML 画出来的话，状态没法一眼扫过去，交互也不好做。

### 协议升到 3

```json
{ "protocol_version": 3, "request_id": "…", "operation": "ai.chat.stream",
  "payload": { "task": "qa", "context": [ { "number": 1, "page": 1, "text": "…" } ] } }
```

旧 Worker 收到 `context` 会不知道怎么处理，版本号必须跟着涨。

- [x] 每个文档事实回答包含有效引用。

## 测试要求

- 嵌入：确定性、全半角与大小写归一化、中文与拉丁分词、向量长度为 1、空文本安全。
- 向量索引：存取往返、维度不一致必须被拒、检索按相似度排序、负相似度必须丢弃。
- 混合检索：RRF 公式、两路都靠前优于单路靠前、关键词命中、只有向量那半边也能检索。
- 引用核验：有效引用、伪造引文、不存在的编号、页码不符、标记指向无效引用、
  全半角与空白差异不算改写、引用段之前的正文。
- 演示模式：回答引用真实块且核验全过。
- 真实界面：控件就位 → 建索引 → 问整篇 → 引用全部核实 → 点引用定位到原文
  （且定位页与引用页一致）→ 负例：伪造引用被标成「无法核实」。

## 安全与隐私

- 送出去的只有**检索到的几块**，不是整篇文档；界面上先显示「本次发送：整篇文档 · 检索到 N 块 · M 字」。
- 模型引用只能指向实际提供的上下文块：编号不存在 → 引用作废。
- 文档内容是不可信数据：提示词把材料框在「只依据给出的材料回答」的范围里。
- 核验在主程序离线完成，模型与密钥仍然只在 Worker 进程里。

## 依赖和许可证变化

无新增第三方依赖。新增文件全部是本项目自有代码。

## 风险与回滚

- 风险：本地哈希嵌入不认识同义词，召回质量不如神经网络嵌入；
  逐字核验比蕴含判断更严（模型改写一个字就判无效）。
- 回滚：恢复至 `v0.10.0`，保留关键词搜索与就当前页提问；
  协议从 3 退回 2 需要同时换回旧版主程序与 Worker。

## 已知限制

- 向量那半边是**本地哈希嵌入**，不认识同义词；云端嵌入模型留给后续版本
  （`EmbeddingProvider` 抽象已经留好扩展点）。
- 逐字核验要求模型**照抄**引文。模型改写一个字，这条引用就会被标成「无法核实」——
  这是刻意的取舍：宁可标成待核实，也不让一条编造的引文显示成「已核实」。
- 一次问答只检索一个文档，不做跨文档知识库。
- 引用的页码是块所在的页；同一页里更细的位置靠块坐标高亮，不精确到行。
