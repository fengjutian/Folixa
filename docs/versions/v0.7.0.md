# v0.7.0 — 基础批注与撤销重做

**状态：** In Progress  
**唯一主要任务：** 实现基础批注的创建、修改、删除以及撤销重做。  
**前置版本：** v0.6.0

## 用户价值

用户可以用高亮、下划线、删除线、便签、矩形和墨迹标记文档，并且每一步都能安全撤销。

## 范围

### 范围内

- 六种批注：高亮、下划线、删除线（基于文字选区），便签、矩形、墨迹（基于页面区域）。
- 批注领域模型、可序列化编辑命令与统一撤销栈（对应技术设计第 6.3、16.3 节）。
- 批注面板：列出全部批注、跳转到所在页、删除批注。
- 批注写进 PDFium 文档，成为文档里真实的注释对象。

### 范围外

- 存盘与另存为：属于 v0.8.0「实现页面管理和安全保存」。
- 协作批注（评论回复）与高级图章。
- 批注颜色选择器：属性面板本版本只提供类型、颜色与正文的展示，修改颜色留给后续版本。
- 墨迹的多笔画合并：一次拖拽 = 一条笔画 = 一条批注。

## 设计决策

### 编辑走命令，进统一撤销栈

技术设计第 6.3 节要求编辑以可序列化命令表达、并进入统一撤销栈。落实为三层：

- `src/pdf/Annotation.*`：批注数据（纯数据，不依赖 PDFium 头文件）。
- `src/doc/`：`AnnotationModel`（当前状态）、`EditCommand`（可序列化命令）、`UndoStack`（统一撤销栈）。
- `src/app/AnnotationController`：把三者与 PDFium 文档串起来。

命令用 JSON 序列化（`QJsonDocument`），因此可以落审计记录、也可以在别处重放。撤销与重做都只是「反向执行命令」。

### 批注坐标一律用 PDF user space

与字符框、链接矩形同一坐标系（左下原点），批注可以直接交给 PDFium 写进文档，中间不用换算。画到屏幕上时由 `PageTransform` 转到显示空间——旋转页上的批注因此和文字层严格对齐。

### 显示由应用层绘制，写入仍走 PDFium

**这是本版本最重要的一个结论，来自实测而不是推断。** PDFium 159 只渲染**自带外观流（/AP）**的批注，而新建的批注没有 /AP；实测（`build/probe/annot_probe*.cpp`）表明：

1. `FPDFPage_CreateAnnot` 能正常创建批注，矩形、颜色、四角点都能写进去，也能读回来；
2. 但用 `FPDF_RenderPageBitmap(..., FPDF_ANNOT)` 渲染时，**新建批注一个像素都画不出来**（前后渲染差异 = 0）；
3. `FPDFAnnot_SetAP` 写外观流在本版本直接返回 `false`；即便成功，PDFium 也只是把内容写进 `/AP` 字典、**不建独立 XObject**，上游要打补丁（pdfium commit `b54d7ad`）才能生成合规的 AP 流，其他阅读器同样不认。

因此本版本的分工是：

- **数据**：批注模型是唯一真相，并投影进 PDFium 文档（`PdfPage::setAnnotations`），使批注成为文档里真实的注释对象，为 v0.8.0 存盘做准备；
- **显示**：由画布按模型绘制（`PageCanvas::paintAnnotations`），效果可控、与选区高亮同一套路。

代价（已知限制）：存盘后，其他阅读器看到的是没有外观流的批注，外观可能不一致；这一项连同外观流生成方案一并放在 v0.8.0 解决。

### 写入是「模型 → 文档」的单向投影

`PdfPage::setAnnotations` 先删掉上一次由本类写入的批注，再写新的。批注总是追加在页面原有批注之后，所以记录「写了多少条」就能知道该从哪个下标开始删。撤销因此只是「重新投影一次」。

### 工具模式与选区动作分开

高亮、下划线、删除线作用于**已有选区**，是工具栏上的动作；便签、矩形、墨迹要接管画布鼠标，是**画布工具模式**。两者混在一起会让「点了链接却画了个矩形」这类歧义出现。

## 验收标准

- [ ] 所列六种批注可以创建、编辑和删除。
- [ ] 每项操作都可以撤销和重做。
- [ ] 批注写进 PDFium 文档后可以读回，撤销后文档里的批注同步消失。
- [ ] 批注面板列出全部批注，点击可跳转到所在页。
- [ ] 软件显示版本为 `0.7.0`。

> 原计划中的「保存后由常见阅读器正确显示」移入 v0.8.0：PDFium 159 的公开 API 无法为新建批注生成合规外观流（见「设计决策」中的实测结论），本版本不承诺跨阅读器的外观一致性。

## 测试要求

- 页面旋转、缩放、跨页操作和反复撤销重做。
- 撤销栈深度上限、分叉后重做栈失效。
- 命令序列化往返：序列化 → 反序列化 → 执行，结果与原命令一致。
- 批注写进文档 → 读回 → 删除 → 读回（批注数与矩形都对得上）。

## 安全与隐私

- 批注正文一律按**纯文本**处理：不解释富文本、不执行脚本、不加载外部内容。
- 批注只写入当前文档，不外发。

## 依赖与许可证

- 不引入新依赖。批注与撤销栈只用 Qt Core（QObject、QJsonDocument）。
- PDFium 仍是 chromium/8152 预编译包，许可证材料不变。

## 风险与回滚

- 风险：不同阅读器的批注外观兼容性不一致（已知的 PDFium 外观流限制）。
- 风险：批注显示由应用层绘制，与 PDFium 原生渲染的批注（文档原有的批注）并存，可能出现两套视觉。
- 回滚：恢复至 `v0.6.0`。
