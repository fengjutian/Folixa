# v0.1.0 — Qt 与 AI Worker 工程骨架

**状态：** Released
**唯一主要任务：** 建立可以构建、启动并完成本地 IPC 健康检查的 Qt 主程序与独立 AI Worker。
**前置版本：** 无
**发布标签：** `v0.1.0`

## 用户价值

开发团队获得稳定的桌面应用和 AI 进程基础，后续 PDF 与模型能力可以在明确边界内迭代。

## 范围

### 范围内

- C++20、Qt 6、CMake 和 vcpkg 工程。
- Qt Widgets 主窗口、多文档标签和 AI 面板框架。
- 独立 `PdfAiWorker` 进程。
- 版本化 JSON Lines 本地 IPC。
- Worker 启动、连接重试、健康检查、超时和退出处理。
- IPC 协议单元测试和基础项目文档。

### 范围外

- PDF 打开和渲染。
- 真实模型 Provider。
- 文档索引、OCR和编辑功能。
- 正式安装包。

## 设计决策

- AI 能力放入独立进程，避免阻塞或破坏 UI 主进程。
- M0 使用 Qt Local IPC；协议保持版本化，以便后续替换传输层。
- Worker 不具备任意文件、网络、Shell或进程执行权限。
- Qt 使用官方二进制套件并固定精确版本，不通过 vcpkg 源码构建 Qt；
  `vcpkg.json` 保留为第三方依赖清单入口，由 v0.2.0 负责可复现依赖环境。
- 主程序与 Worker 的可执行文件输出到同一个 `bin` 目录，主程序按自身路径查找 Worker。

## 构建环境

固定组合（已在本机安装并验证）：

| 组件 | 版本 | 来源 |
|---|---|---|
| Qt | 6.8.3 `mingw_64` | `aqt install-qt windows desktop 6.8.3 win64_mingw --outputdir C:\Qt --archives qtbase` |
| MinGW-w64 | GCC 13.1.0 | `aqt install-tool windows desktop tools_mingw1310 qt.tools.win64_mingw1310 --outputdir C:\Qt` |
| CMake | 4.3.3 | 系统安装 |
| Ninja | 1.11 | 系统安装 |

工具链路径写在 `cmake/toolchains/qt-mingw.cmake`，可用环境变量 `AIPDF_QT_ROOT`、
`AIPDF_MINGW_ROOT` 覆盖。

```powershell
cmake --preset windows-debug
cmake --build --preset windows-debug
ctest --preset windows-debug
```

## 安全与隐私

- IPC 帧限制为 1 MiB。
- Server 名称使用每次会话的随机标识。
- 不保存密钥或文档正文。

## 依赖与许可证

- Qt 6.8.3（LGPL v3，动态链接），来源与分发策略记录在 `THIRD_PARTY_LICENSES.md`。
- MinGW-w64 GCC 13.1.0（GPLv3 + GCC Runtime Library Exception），仅作为构建期工具链，
  运行时随包分发的是 Qt 官方套件自带的运行库。
- 精确版本与分发策略将在 v0.2.0 再次固定。

## 风险与回滚

- 风险：当前只验证了 Qt 6.8.3 + MinGW-w64 组合，未验证 MSVC 工具链；
  Qt 官方套件升级需要重新跑验收。
- 回滚：该版本为首个版本，无前置发布标签。

### 已知问题

1. 主程序被强制结束（任务管理器 Kill）时，已拉起的 Worker 会残留；
   M0 没有看门狗进程，后续版本处理。
2. Windows 命名管道在客户端没有待读数据时不会主动上报对端断开，
   因此 Worker 异常退出的感知依赖客户端自己持有的 `QProcess` 结束信号。
3. 构建依赖 Qt 官方二进制套件，尚未引入 vcpkg 与 SBOM，属 v0.2.0 范围。
