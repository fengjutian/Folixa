# v0.2.0 — 可复现的 Windows 构建环境

**状态：** Verification
**唯一主要任务：** 建立能够从干净环境重复构建、测试和打包 v0.1.0 功能的 Windows x64 工具链。
**前置版本：** v0.1.0

## 用户价值

任何开发者或 CI 环境都能按文档产生一致、可验证的软件包。

## 范围

### 范围内

- 固定 Qt、MinGW-w64、CMake、Ninja 和 vcpkg 版本。
- Debug/Release Preset、CI、测试、部署和依赖复制。
- 生成依赖清单和许可证材料。
- 产生可启动的 Windows x64 ZIP 开发包。

### 范围外

- PDFium和 PDF 功能。
- 正式签名安装程序和自动更新。

## 设计决策

- **工具链以 MinGW-w64 替代 Visual Studio。** v0.2.0 原计划固定 Visual Studio 版本，
  但本机为非管理员会话，Visual Studio Build Tools 的安装需要 UAC 提权，
  无法在无人工干预的环境中完成。Qt 官方二进制套件提供 `win64_mingw` 架构，
  与官方 MinGW-w64 GCC 13.1.0 工具包配套，可完全绕开 MSVC，且与 CI 使用的
  `windows-2022` 运行环境一致。该偏离在此显式记录，不做静默替换。
- **Qt 用官方二进制套件而不是 vcpkg 源码构建。** vcpkg 构建 qtbase 需数小时，
  与「干净环境可重复构建」的目标冲突；vcpkg 保留为后续第三方依赖入口，
  以 `builtin-baseline` 固定版本。
- **打包用脚本而不是 CPack 模板。** Qt 运行库部署、许可证材料、SBOM 生成和
  验收是同一条链路，脚本化后 CI 与本地跑的是同一段代码。
- **打包目录结构沿用 windeployqt 输出。** Qt 6 的平台插件位于程序目录下的
  `platforms/`，不是 `plugins/platforms/`；已用「无 SDK 环境启动」实测确认。

## 安全与隐私

- 构建日志和制品不包含密钥。
- 依赖下载来源和哈希可追踪。 → `aqtinstall` 校验官方哈希；
  制品内每个文件在 SBOM 中记录 SHA-256，ZIP 旁附 `.sha256`。

## 依赖与许可证

- Qt 6.8.3（LGPL v3，动态链接）与 MinGW-w64 GCC 13.1.0（GPLv3 + GCC Runtime
  Library Exception）版本、来源与分发策略记录在 `THIRD_PARTY_LICENSES.md`。
- 每次打包生成 CycloneDX 1.5 SBOM（`sbom/ai-pdf-editor-<版本>.cdx.json`），
  逐文件记录 SHA-256 与许可证，并附带 Qt 官方自带的 SPDX SBOM。

## 风险与回滚

- 风险：当前只在 MinGW 工具链上验证，MSVC 路线尚未验证；
  CI 首次运行前无法确认 `windows-2022` 环境的完整复现。
- 回滚：恢复至 `v0.1.0`。

## 完成记录

### 已交付

- `scripts/bootstrap-toolchain.ps1`：固定安装 Qt 6.8.3 与 MinGW-w64 GCC 13.1.0，可重复执行。
- `cmake/toolchains/qt-mingw.cmake`：固定编译器与 Qt 路径，支持环境变量覆盖。
- `vcpkg.json`：以 `builtin-baseline` 固定 vcpkg 版本。
- `scripts/package.ps1`：部署 Qt 运行库、收集许可证材料、生成 NOTICE 与 SBOM、压缩并输出 SHA-256。
- `scripts/generate-sbom.ps1`：生成 CycloneDX 1.5 SBOM。
- `scripts/verify-package.ps1`：在清空 Qt SDK 的 PATH 环境中验证安装包可独立运行。
- `scripts/AcceptanceProbe.ps1`：验收脚本共用的 UI Automation 探针与窗口截图。
- `.github/workflows/windows.yml`：Debug/Release 构建、测试、验收、打包与制品上传。
- CMake 新增 `package` 目标与安装规则。
