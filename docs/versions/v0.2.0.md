# v0.2.0 — 可复现的 Windows 构建环境

**状态：** Verification
**唯一主要任务：** 建立能够从干净环境重复构建、测试和打包 v0.1.0 功能的 Windows x64 工具链。
**前置版本：** v0.1.0

## 用户价值

任何开发者或 CI 环境都能按文档产生一致、可验证的软件包。

## 范围

### 范围内

- 固定 Qt、MinGW-w64、CMake、Ninja 和 vcpkg 版本。
- Debug/Release Preset、CI、测试、部署和依赖复制。
- 生成依赖清单和许可证材料。
- 产生可启动的 Windows x64 ZIP 开发包。

### 范围外

- PDFium和 PDF 功能。
- 正式签名安装程序和自动更新。

## 设计决策

- **工具链以 MinGW-w64 替代 Visual Studio。** v0.2.0 原计划固定 Visual Studio 版本，
  但本机为非管理员会话，Visual Studio Build Tools 的安装需要 UAC 提权，
  无法在无人工干预的环境中完成。Qt 官方二进制套件提供 `win64_mingw` 架构，
  与官方 MinGW-w64 GCC 13.1.0 工具包配套，可完全绕开 MSVC，且与 CI 使用的
  `windows-2022` 运行环境一致。该偏离在此显式记录，不做静默替换。
- **Qt 用官方二进制套件而不是 vcpkg 源码构建。** vcpkg 构建 qtbase 需数小时，
  与「干净环境可重复构建」的目标冲突；vcpkg 保留为后续第三方依赖入口，
  以 `builtin-baseline` 固定版本。
- **打包用脚本而不是 CPack 模板。** Qt 运行库部署、许可证材料、SBOM 生成和
  验收是同一条链路，脚本化后 CI 与本地跑的是同一段代码。
- **打包目录结构沿用 windeployqt 输出。** Qt 6 的平台插件位于程序目录下的
  `platforms/`，不是 `plugins/platforms/`；已用「无 SDK 环境启动」实测确认。

## 完成记录

### 已交付

- `scripts/bootstrap-toolchain.ps1`：固定安装 Qt 6.8.3 与 MinGW-w64 GCC 13.1.0，可重复执行。
- `cmake/toolchains/qt-mingw.cmake`：固定编译器与 Qt 路径，支持环境变量覆盖。
- `vcpkg.json`：以 `builtin-baseline` 固定 vcpkg 版本。
- `scripts/package.ps1`：部署 Qt 运行库、收集许可证材料、生成 NOTICE 与 SBOM、压缩并输出 SHA-256。
- `scripts/generate-sbom.ps1`：生成 CycloneDX 1.5 SBOM。
- `scripts/verify-package.ps1`：在清空 Qt SDK 的 PATH 环境中验证安装包可独立运行。
- `scripts/verify-sbom.ps1`：发布门——包内每个文件都必须在 SBOM 中登记且哈希一致。
- `scripts/verify-licenses.ps1`：发布门——安装包必须随附第三方许可证全文且与校验清单一致。
- `scripts/fetch-licenses.ps1`：取得并校验许可证全文（`licenses/CHECKSUMS.txt` 为准）。
- `licenses/`：随包分发的 LGPL-3.0、GPL-3.0、GCC 运行时例外全文及来源说明。
- `scripts/check-version.ps1`：发布门——CMake / vcpkg / 版本文档 / 索引状态 / 可执行文件版本必须一致。
- `scripts/test-gates.ps1`：上面各门的负例守卫，故意弄坏输入，门必须变红。
- `scripts/ci.ps1`：本地与 CI 共用的单一流水线入口。
- `scripts/AcceptanceProbe.ps1`：验收脚本共用的 UI Automation 探针与窗口截图。
- `.github/workflows/windows.yml`：调用 `scripts/ci.ps1`，并上传安装包与验收证据。
- CMake：新增 `package` 目标、安装规则、Qt 运行库自动部署、Windows 版本资源。

### 本轮修复的问题

1. **构建树不是自包含的。** 测试与验收依赖开发机上的 Qt SDK 路径，
   在没有 Qt 的机器上直接报 `0xc0000135`（DLL 找不到）。
   现在构建后由 CMake 调用 windeployqt 把运行库与平台插件部署到 `bin`，
   清空 Qt 的 PATH 也能跑测试。
2. **部署方式固定为动态链接。** 用 windeployqt 显式部署，
   保证符合 LGPL 动态链接要求，而不是让构建系统自行选择链接方式。
3. **可执行文件没有版本资源。** MinGW 目标默认不嵌入 VERSIONINFO，
   文件属性里查不到版本号。现在用 `cmake/version.rc.in` 注入，
   `FileVersion` 与项目版本一致。
4. **版本一致性没有机检。** 现在 `check-version.ps1` 会核对 CMake、vcpkg 清单、
   版本文档、索引状态、exe 版本和安装包名称，并强制「同一时间只有一个 In Progress 版本」。
5. **发布门缺少负例。** `test-gates.ps1` 会篡改 SBOM 哈希、删掉条目、改错版本号、
   篡改许可证全文、改乱 vcpkg 版本、制造两个 In Progress 版本，逐项确认门会变红。
6. **安装包缺许可证全文。** `aqtinstall` 套件不含许可证文件。
   现在仓库内 `licenses/` 保存 LGPL-3.0、GPL-3.0 与 GCC 运行时例外全文，
   打包时随附，并由 `verify-licenses.ps1` 按 `CHECKSUMS.txt` 校验。
