# v1.4.0 — 批注互操作与审阅

**状态：** Planned  
**唯一主要任务：** 把批注类型、审阅流程与数据交换补齐到与福昕同水平（对标项 C1–C12）。  
**前置版本：** v1.3.0

## 用户价值

用户能用完整的批注工具做审阅——文本框、图章、箭头、云线、测量、附件——并且这些批注在别人的阅读器里长得一样；审阅意见可以回复、标记状态、导出给同事汇总。

## 范围

### 范围内

- 批注类型：波浪线、文本框/打字机、椭圆、线条、箭头、多边形、云线、图章（内置 + 自定义图片）、附件、声音、测量（距离/周长/面积 + 比例尺）。
- 墨迹橡皮与笔画编辑。
- 回复线程（`/IRT`）、审阅状态（`/State`）、作者与时间。
- XFDF / FDF 导入导出；批注摘要（HTML / PDF / 打印）。
- 批注属性面板：颜色、线宽、透明度、字体、锁定。

### 范围外

- 实时协同审阅、云端评论服务。
- 3D 批注、影视批注。

## 设计决策

### 类型扩展只改三处，不许出现第四处

新增一种批注要动的只有：`AnnotationType` 枚举、`annotationTypeToPdfium()` 映射、`AppearanceStreamBuilder` 的外观分支。属性编辑、撤销、面板列表、序列化都走既有泛化路径——一旦某个新类型需要"特殊处理"，说明抽象错了，先改抽象。

### 测量的正确性靠 `/Measure` 字典，不靠像素

距离/周长/面积的数值必须写进 `/Measure`（`/R` 比例、`/X` 单位、`/D` 显示格式），否则换个阅读器数值就没了。视觉上的标尺线是"外观"，数值是"数据"，两者都要写。

### 回复用标准线程，不用自定义 JSON

`/IRT` 指向父批注，`/RT /R` 表示回复。自定义结构在本程序里好看，导出到别人那里就成了一堆孤立批注。审阅状态用 `/State` + `/StateModel`（`Review`/`Marked`），同样为了互操作。

### XFDF 是坐标转换问题，不是格式问题

XFDF 的坐标是 PDF user space，颜色是 `#RRGGBB`，日期是 `D:YYYYMMDDHHmmSS`。坑在于：同一个批注在 CropBox ≠ MediaBox 的页面上，坐标基准不同。转换必须集中在 `AnnotationCodec` 一处，并且用"导出→导入→再导出"的往返测试守住。

### 摘要先做 HTML，不做排版引擎

批注摘要要能贴进邮件、能打印。做法是把批注列表渲染成一张 HTML 表（页、作者、类型、内容、截图缩略），再用已有的打印路径输出 PDF。不引入报表引擎。

## 实施步骤

- [ ] 批注模型扩展：新类型、属性、回复、状态，序列化向后兼容。
- [ ] 外观流：11 种类型的外观生成（复用 1.3.0 的生成器）。
- [ ] 交互工具：绘制、编辑、橡皮、图章放置、测量取点。
- [ ] 属性面板与批量改属性。
- [ ] XFDF/FDF 编解码 + 往返测试。
- [ ] 摘要：HTML 生成、缩略图、打印/导出。
- [ ] 验收脚本 `scripts/verify-annotation-types.ps1`。

## 验收标准

- [ ] 11 种批注在本程序、福昕、Acrobat 中外观一致（像素比对，容差 ≤3px）。
- [ ] 测量值在三个阅读器中一致，误差 <0.5%。
- [ ] 回复线程与状态在福昕中正确显示为回复。
- [ ] XFDF 往返三次后，批注数量、位置、内容、颜色不变。
- [ ] 摘要包含全部批注，页码与作者正确。
- [ ] 批注属性修改可撤销，撤销后外观流同步更新。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 类型：旋转页、裁剪页、小页面（批注超出边界）、中文字体、自定义图章尺寸。
- 互操作：用福昕导出的 XFDF 导回来；用福昕加的批注我们能读能改。
- 压力：单页 500 条批注的渲染与面板性能。

## 安全与隐私

- 附件批注可以嵌入任意文件：导入时必须显示文件名、类型、大小并二次确认；不自动执行、不自动解压。
- 自定义图章图片只接受位图，限制尺寸与像素总量，防解码炸弹。

## 依赖与许可证

- 无新增第三方（XML 用 Qt 自带）。

## 风险与回滚

- 风险：批注类型增多导致面板与属性逻辑膨胀、互操作细节回归。
- 回滚：新类型可逐个关闭入口；数据格式向前兼容，旧版本仍能打开文档；恢复至 `v1.3.0`。
