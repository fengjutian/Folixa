# v0.10.0 — 流式 AI 对话

**状态：** In Progress  
**唯一主要任务：** 接入首个云端模型 Provider，并在 AI 面板中提供可取消的流式对话。  
**前置版本：** v0.9.0

## 用户价值

用户可以在应用内获得当前页摘要、选中文本解释和翻译结果；没有配置密钥时也有可用的演示路径，不会看到一个坏掉的 AI 面板。

## 范围

- Provider 抽象与一个 OpenAI 兼容实现（流式、取消、重试、超时、用量）。
- 演示 Provider：没有密钥时接管，界面上显式标注「演示模式」。
- AI 面板：总结 / 解释 / 翻译 / 就当前页提问，流式显示、停止、用量与估算费用。
- API 密钥设置界面：密钥存 Windows 凭据管理器，配置不含秘密。
- IPC 协议升到 2：新增 `event` 帧承载流式增量。
- 范围外：文档级 RAG（v0.11.0）、隐私策略（v0.12.0）、OCR（v0.13.0）、AI 改文档（v0.14.0）。

## 设计决策

### 对标：开源桌面 AI 客户端怎么做

动手前先查了同领域的成熟实现（Open WebUI、Cherry Studio、Continue.dev）：

| 做法 | 对标来源 | 本项目的取法 |
|---|---|---|
| Provider 分层：每个服务一个实现，共用请求/响应模型 | Open WebUI 的 provider 层 | `src/ai/ModelProvider.h` 抽象 + `ProviderFactory` 造实例 |
| SSE 增量解析，不做整包缓冲 | Open WebUI 的 `aiter_bytes` | `src/ai/SseParser.h` 纯状态机，可单测 |
| 按请求新建 Provider 客户端 | Open WebUI | Worker 每次 `ai.chat.stream` 重新读配置与凭据再建 Provider |
| API Key 放系统凭据库，不放自己的配置文件 | Cherry Studio | `src/ai/CredentialStore.h`：Windows Credential Manager（DPAPI） |
| 价格随模型走，不写死在代码里 | — | 单价写进 `ProviderConfig`，服务商改价改配置 |

### Provider 放在 Worker 进程，不放主程序

沿用现有的「独立 `PdfAiWorker` + `QLocalSocket`」架构：主程序不碰网络，也不碰密钥。

- 主程序只发**已经拼好的提示词**，不发密钥；
- 密钥在 Worker 里读，读完只交给 Provider，不进 IPC 帧、不进日志、不进轨迹；
- 主程序被关掉时，Worker 里的流式请求随之取消，不会留下挂着的 HTTP 连接。

代价是主程序与 Worker 要共享一份配置（地址、模型名、单价、超时）。这份配置放在
`%LOCALAPPDATA%\Folixa\ai\config.json`。

**不能用 `QStandardPaths::AppLocalDataLocation`**：那个路径带应用名，
主程序叫 `AiPdfEditor`、Worker 叫 `PdfAiWorker`，两个进程会找到**不同目录**，
主程序改了设置 Worker 读不到。所以路径要自己算：读 `LOCALAPPDATA` 再拼 `Folixa`。

### 没配密钥 → 演示模式，不报错退出

第一次打开应用的人没有密钥。如果这时 AI 面板报错退出，用户看到的就是一个坏掉的按钮。

规则：**配了密钥用真的，没配用演示模式**。演示模式（`MockProvider`）不是「假的成功」——
它按任务生成一段像样的中文答复，并且**逐段流式吐出来**，所以流式链路（增量、取消、用量）
在演示模式下也是真的跑通的，只是回答内容由本地拼出来。

但界面**必须显式标注**：状态行写「演示模式（未配置密钥）· 回答由本地拼出，不会发到网络」，
回答正文也带「【演示模式】」前缀。不能让人以为模型真的回答了。

### 数据范围：先展示，再上传

送出去的内容只有**当前页文本**或**当前选区**，绝不默认送整份文档。上限 4000 字，超出截断并说明。

每次发送前，界面先显示「本次发送：第 N 页 · M 字（已截断）」，并写进轨迹
（`ai scope page=… chars=… task=…`）。用户看得见送了什么，验收也断言得出来。

四个任务各有固定的系统提示词，全部要求「只依据给出的材料回答」，
摘要与解释还要求写出处（页码）——为 v0.11.0 的引用验证留接口。

### 密钥只进 Windows 凭据管理器

`CredWriteW` / `CredReadW`，`CRED_TYPE_GENERIC` + `CRED_PERSIST_LOCAL_MACHINE`。
底层是 DPAPI，加密后的数据与当前用户的 Windows 登录会话绑定。

明确不做的事：密钥不写进普通配置文件、不进日志、不进崩溃报告、不随 IPC 帧回传主程序。
配置里只存「去哪个名字下取密钥」（`Folixa/ai/<provider>/api-key`）。

凭据管理器存的是字节串，UTF-16 的 blob 要按**字节**算大小并带上结尾的 0。
两个宽字符串都必须是有名字的局部变量——写成 `const_cast<LPWSTR>(toWide(x).c_str())` 的话，
临时对象在这一行结束就没了，`CredWriteW` 拿到的是野指针。

### 重定向不自动跟随

`QNetworkRequest::ManualRedirectPolicy`：跟随 302 会把 `Authorization` 头带到另一个主机上，
密钥就跟着出去了。服务地址配错了应该直接报错，而不是悄悄把密钥递出去。

### 事件帧：中间消息不能长得像最终结果

IPC 协议从 1 升到 2，新增 `type: "event"`：

```json
{ "protocol_version": 2, "request_id": "…", "type": "event",
  "event": "ai.stream.delta", "payload": { "text": "增量" } }
```

**事件帧刻意不带 `ok` 字段**：`ok` 只属于最终结果。谁把中间事件当成「请求成功了」，
一眼就该看出来。客户端看到 `type == "event"` 就不能停掉挂起的定时器、不能清流式状态——
否则界面会提前显示「已完成」。

流式请求**不挂超时定时器**：靠取消与 Worker 的错误事件收尾。

### 价格写进配置，不写死

`estimatedCost()` 只做乘法，单价来自 `ProviderConfig`：

```cpp
(inputTokens / 1'000'000.0) * inputPricePerMillion
+ (outputTokens / 1'000'000.0) * outputPricePerMillion
```

服务商改价时改配置，不改代码，也不需要重新打包。

### 演示模式的吐字速度做成可调

`MockProvider` 认环境变量 `AIPDF_AI_MOCK_DELAY_MS`（默认 30ms 一段）。

原因很实际：默认速度下答案 1 秒内就吐完了，「点停止」会慢一步，**取消功能的验收时序不确定**。
验收脚本把它调到 250ms，这条流变长，取消才是确定能测出来的。

## 测试要求

- SSE：半行、半事件、注释行、多 data 行、`\r\n`、事件名、flush 尾巴、reset。
- 提示词：四个任务的系统提示词都必须带范围约束；材料与问题都要进用户消息。
- 费用：按配置单价算；没配单价时是 0。
- 凭据：存取往返、目标名按服务商区分、空名失败、配置文件里没有密钥。
- 配置：存取往返、缺文件回落默认值、非法地址与非法模型被拒。
- 协议：事件帧不是最终结果（不带 `ok`）、一帧一行、协议版本为 2。
- 真实界面：面板就位（演示模式标注）→ 流式总结与用量 → 就当前页提问 →
  取消正在进行的生成 → 设置对话框打开与取消。

## 安全与隐私

- 上传前展示数据范围；默认不上传整份文档；上限 4000 字。
- 密钥只在 Windows 凭据管理器里，不进配置文件、日志、轨迹与 IPC 帧。
- 不自动跟随重定向，避免 `Authorization` 头被带到别的主机。
- 文档内容是不可信数据：提示词把材料框在「只依据给出的材料」的范围里，
  模型不得据此改文档（AI 改文档留给 v0.14.0，且必须转为可验证、可撤销的命令）。

## 依赖和许可证变化

无新增第三方依赖。新增系统库链接 `advapi32`（Windows Credential Manager），
属于操作系统组件，不进入第三方许可证清单。

## 风险与回滚

- 风险：外部服务可用性、费用与数据政策变化；服务商的 SSE 字段与本实现不完全一致。
- 回滚：把 `ProviderConfig.providerId` 改回 `demo` 即回到演示模式；
  整体回滚则恢复至 `v0.9.0`（旧客户端不认协议 2，必须同时换回旧版主程序）。

### 被测试抓出的缺陷

1. **Qt 6 没有 `QNetworkRequest::AcceptHeader`**：编译期直接报「不是 QNetworkRequest 的成员」。
   改成 `setRawHeader("Accept", "text/event-stream")`。
2. **事件帧带了 `ok` 字段**：单测断言「事件帧不能自带 ok」当场变红。
   这不是洁癖——`ok` 属于最终结果，中间消息带着它，正是「把中间事件当成最终结果」最容易犯的错。
3. **翻译任务的提示词没有「只依据」**：单测按「四个任务的系统提示词都必须带范围约束」
   断言时把它抓了出来。改写措辞后四个任务的口径一致，这条约束也才真的可测。
4. **流式请求的状态永远清不掉**：Worker 只发结束事件、不发最终结果帧，
   客户端的 `activeStreams_` 里那个 id 就一直留着——`isStreamActive()` 对早就结束的流
   还在说「进行中」，集合也只增不减。改成**每个请求都以一个最终结果帧收尾**，
   客户端在收到它时清状态。加了集成测试守着（去掉最终结果帧，测试立刻变红）。
5. **Worker 的错误帧被界面忽略**：Worker 回 `type: "error"` 时，客户端只发
   `responseReceived`，而 AI 面板只监听 `requestFailed`——于是「上一次生成还没结束」
   这类错误**用户一点都看不到**，界面像是没反应。改成错误帧同时报成失败，
   并把 Worker 侧的消息改成中文（错误帧的文案是直接显示给用户的）。
   守卫测试的负例验证：把修复去掉，`busyStreamIsReportedAsFailure` 当场变红。
6. **没有文本层的页面会把面板卡在「正在提取…」**：文本层已经在手边、但排版结果为空时，
   `requestTextPage()` 不会再发 `textPageReady`，等待就永远等不到下文。
   改成认出「这一页没有文字层」并立刻给出提示。

### 已知限制

- 只支持 OpenAI 兼容的 SSE 协议（`/chat/completions`）。Anthropic、Gemini 等
  各自有事件格式，需要各写一个 Provider——`ModelProvider` 的抽象就是为这个留的。
- 只有一个演示模式与一个云端实现；没有多 Provider 切换界面（设置里可以改地址与模型名）。
- 费用是按配置单价**估算**的，服务商若返回了真实用量则以返回值为准。
- 摘要/解释/翻译的出处页码由模型自己写，属于「尽力而为」，
  真正的引用验证与原文定位留给 v0.11.0。
- 演示模式不是模型输出，不能用来评估真实模型的质量。
- v0.9.0 遗留：移动页会打断该页内部链接与指向该页的链接（PDFium 159 无公开接口可修），本版未改动。
