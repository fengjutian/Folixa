# v1.9.0 — 转换、优化与 PDF/A

**状态：** Planned  
**唯一主要任务：** 提供格式转换、文件优化与 PDF/A 合规输出（对标项 H5–H8）。  
**前置版本：** v1.8.0

## 用户价值

用户可以把 PDF 转成 Word 继续编辑、把扫描件或图片做成 PDF、把文件压小方便发送，也能交付归档要求的 PDF/A 文件。

## 范围

### 范围内

- PDF → Word（基础版：段落、标题、列表、图片；**不保证版式还原**）。
- 任意文件 → PDF（调用系统中可用的转换器：LibreOffice、Office 打印驱动；检测不到就隐藏入口）。
- PDF/A-2b 转换：OutputIntent（sRGB）、XMP 元数据、字体嵌入检查、禁用不允许的特性。
- 内置 PDF/A 子集校验器（不依赖 Java）。
- 优化：对象流/交叉引用流、字体子集化、图像降采样与重编码、无引用对象清理。
- 优化前后的体积与质量报告。

### 范围外

- 商业转换 SDK（Solid/Adobe/Foxit）——**不引入**，这是本项目的依赖红线。
- Office → PDF 的版式保真（取决于外部转换器）。
- PDF/UA（J6 明确不做）。

## 设计决策

### 转换只承诺"可验证的部分"

PDF→Word 的版式还原是行业难题，商业产品也做不到 90%。与其做一个"看起来像但到处错位"的转换器，不如明确边界：

- 做：段落与标题结构、列表、图片、基本字体与字号、超链接；
- 不做：浮动定位、分栏、表格跨页、文本框内的复杂排版；
- 界面在转换前就写明"版式可能变化，建议用于内容复用"。

### 外部转换器是可选增强，不是依赖

"任意文件 → PDF"需要 Office 排版引擎。自研不可能，打包 LibreOffice 会让安装包从 20MB 变成 300MB+，违背体积翻盘点。

做法：运行时探测（注册表 / 常见安装路径），探测到就显示入口，探测不到就隐藏，并在帮助里说明"安装 LibreOffice 后可启用"。功能降级是显式的，不是静默失败。

### PDF/A 不做"尽力而为"，只做"确定合规"

PDF/A 校验失败的常见原因是字体没嵌入。qpdf 不能嵌字体，PDFium 也没有嵌入接口。所以策略是：

1. **只转换字体已全部嵌入的文档**；
2. 未嵌入字体时直接拒绝，并列出缺失字体名与所在页；
3. 转换后跑内置校验器（XMP、OutputIntent、字体嵌入、禁止项：加密、JavaScript、外部内容、透明度组）；
4. 校验不通过就不产出文件。

宁可"这次转不了"，也不要交付一个"看起来是 PDF/A"的文件——归档场景下假合规比失败更糟。

### 优化必须先测量再动手

优化只有两种结果：变小且无损，或者变糊。所以每次优化都要产出报告：原体积、新体积、各项收益（对象流/字体/图像）、图像降采样后的 PSNR 或直接做像素比对。用户能看到"省了 40%，图像从 300DPI 降到 150DPI"。

## 实施步骤

- [ ] PDF→docx 生成器（OPC 包 + 段落映射 + 图片导出）。
- [ ] 外部转换器探测与调用（超时、临时文件、失败清理）。
- [ ] PDF/A 前置检查（字体嵌入、禁止项）。
- [ ] PDF/A 写出（OutputIntent、XMP、Metadata）。
- [ ] 内置校验器与失败原因明细。
- [ ] 优化器：对象流、字体子集、图像降采样、引用清理。
- [ ] 优化报告（体积、收益、质量）。
- [ ] 验收脚本 `scripts/verify-convert.ps1`。

## 验收标准

- [ ] PDF→docx 产出的文件 Word/WPS 可打开，文本与图片齐全，标题层级正确。
- [ ] 未安装转换器时"任意文件→PDF"入口隐藏且不影响其他功能。
- [ ] PDF/A 产物通过内置校验器；未通过时不产出文件并给出原因。
- [ ] 优化后体积下降 ≥15%（含图像的样本），未优化区域像素完全一致。
- [ ] 优化不破坏批注、表单、书签、签名（签名文档拒绝优化并提示）。
- [ ] Debug 和 Release 构建成功。
- [ ] 自动化测试通过。
- [ ] 软件版本号与本文档一致。

## 测试要求

- 转换：纯文本、双栏、表格、扫描页、竖排、中英混排。
- PDF/A：已嵌入字体的中文文档、缺字体文档（必须拒绝）、带透明度文档。
- 优化：纯矢量、纯扫描、混合、超大图像、已线性化文件。

## 安全与隐私

- 调用外部转换器时使用临时目录与受限参数，不把用户路径拼进命令行（防注入）。
- 转换/优化全程不联网。

## 依赖与许可证

- docx 生成使用 Qt 自带 XML 能力，无新增第三方。
- sRGB ICC profile 需选用公有领域版本并登记来源与许可证。
- LibreOffice 为**可选外部组件**，不随包分发，仅在运行时探测。

## 风险与回滚

- 风险：PDF/A 校验器覆盖不全导致"假合规"；docx 输出质量低于预期引发口碑问题。
- 回滚：转换与优化都是"另存为"，原文件不动；入口可整体隐藏；恢复至 `v1.8.0`。
