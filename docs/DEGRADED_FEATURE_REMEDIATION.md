# 降级功能整改方案

**审计日期：** 2026-11-17  
**对标对象：** Foxit PDF Editor 2026.1.2.36547  
**数据来源：** `docs/FOXIT_BENCHMARK.md`、`docs/benchmark/foxit-features.csv`、`docs/VERSION_AUDIT.md` 与当前源码/测试  
**目的：** 找出已经写成“完成、已具备或对齐”，但实际上只完成了降级路径的能力，并给出能够真正关闭差距的实现与验收方案。

## 1. 审计结论

当前命令矩阵共 276 项：175 项 `aligned`、72 项 `partial`、23 项 `na`、6 项 `excluded`。问题不只是 72 项明确标记为 `partial`：部分 `aligned` 项的备注仍包含“只支持”“未接”“不是”“没有真机验证”等关键限制，因此不能直接把 `aligned` 等同于与福昕同等可用。

本文件采用更严格的完成定义：

1. **入口存在不算完成**：必须从界面走通到持久化结果。
2. **能生成文件不算转换对齐**：必须保留目标格式承诺的主要内容、结构和样式。
3. **结构可写不算运行能力完成**：3D、媒体、XFA、签名等必须能实际消费或明确改名为“结构工具”。
4. **假源单测不算设备能力完成**：扫描仪、OneNote、打印机、读屏软件必须有真机证据。
5. **依赖可选组件的功能不算发布完成**：发布包必须带齐依赖，或安装时明确检测和引导。
6. **“对齐”必须有跨软件验收**：至少使用本项目、福昕和一个独立实现重开验证；视觉功能还要做像素或结构差异比较。

## 2. 状态修正规则

建议把矩阵状态从单轴改成三轴，避免以后继续把降级实现写成完成：

| 轴 | 可选值 | 含义 |
|---|---|---|
| 实现状态 | missing / prototype / usable / complete | 是否有完整用户链路 |
| 对齐状态 | below / partial / aligned / exceeds / excluded | 与福昕的实际差距 |
| 验证状态 | unit / integration / interop / hardware / production | 证据达到哪一层 |

只有 `complete + aligned/exceeds + interop` 才允许在评分卡写“对齐”；设备功能还必须达到 `hardware`。原有的“已具备”只能表示项目内部可用，不能自动计入对齐。

## 3. P0：阻止替代福昕的核心降级

### 3.1 PDF → Office 只是文字导出

**当前降级：** DOCX/RTF 只导一页文字层，不含图片、表格、段落样式；Excel 与 PPT 未实现，却在能力评分卡 H5 写成“对齐”。

**解决方案：**

- 建立中间文档模型 `DocumentModel`：页面、文本块、段落、行、字形、图片、表格、矢量图和阅读顺序。
- 用坐标聚类和字体特征恢复段落；通过线框、对齐和单元格交叉关系识别表格。
- DOCX 使用 OOXML 原生段落、表格、图片和页眉页脚；不要把页面全部截图塞进 Word。
- XLSX 只对检测到的表格开放，保留合并单元格、数字类型和多工作表；不能识别时给预览，不静默输出错误表格。
- PPTX 以 PDF 页面为幻灯片，文字和图片转为可编辑对象；复杂页面允许“背景图 + 可编辑文本层”的保真降级。
- 先支持整篇导出，再做批量转换；保留字体替换报告。

**完成标准：** 50 份含双栏、表格、图片、页眉页脚和 CJK 的语料；DOCX/PPTX 能由 Microsoft Office 和 LibreOffice 打开；页数、图片数、表格数和主要文字一致；渲染差异设分档阈值；Excel 表格单元格结构 F1 ≥ 0.95。

### 3.2 内容编辑与重排会丢对象

**当前降级：** 整篇重排依赖标签树并丢图形、表格、页眉页脚；流式编辑只处理选区；链接文本不能跨文本块。评分卡把 E5/E6 写成对齐会掩盖数据损失风险。

**解决方案：**

- 构建页面对象图，保存文本、图片、矢量、表格和锚点关系，不直接把页面退化为纯文本。
- 把重排分为“阅读重排”和“写回重排”：阅读重排只改变视图，不改 PDF；写回重排必须先显示影响预览。
- 对无标签 PDF 使用版面分析生成临时结构树；置信度不足的块要求用户确认。
- 图片、表格和浮动对象使用锚点随段落移动；页眉页脚独立识别并跨页复用。
- 所有写回操作以对象级命令进入撤销栈；保存前后做对象数量、文字、图片和渲染回归。

**完成标准：** 默认操作不得静默丢对象；取消后字节或对象模型恢复；100 份复杂排版语料保存重开后文字、图片、表格均存在；差异超阈值时阻止覆盖原文件。

### 3.3 PDF 安全解析仍在主进程

**当前降级：** AI 在 Worker 中，但 PDFium 解析、渲染和部分写入仍在 GUI 主进程；“安全文档”因此只有局部隔离。

**解决方案：**

- 新建低权限 `PdfRenderWorker`，把打开、解析、文字提取、缩略图和页面渲染迁出主进程。
- Windows 上使用 Job Object、受限令牌、进程内存/CPU/句柄限额和禁止子进程策略。
- IPC 只传不可执行的结构化数据；大位图使用受控共享内存，附尺寸、格式和校验值。
- 写入流程使用独立 Writer Worker，输出到临时文件，经 qpdf/独立解析器重开验证后再原子替换。
- Worker 崩溃时关闭当前文档、保留应用与未提交命令日志，并提供可脱敏的崩溃报告。

**完成标准：** 恶意/损坏语料导致 Worker 崩溃时 GUI 不退出；超时和内存超限可回收；IPC 模糊测试无越界；发布构建强制启用结构校验，不允许 qpdf 默默缺失。

### 3.4 表单能力缺完整运行时

**当前降级：** 自动识别只枚举已有 AcroForm；JavaScript 是白名单子集；XFA 只提取静态字段；设计助手不做布局、不跨页；“表单到工作表”实际是 CSV。

**解决方案：**

- 自动识别：结合线框/下划线/复选框视觉检测、OCR 标签关联和字段类型分类，输出可编辑候选，不直接写盘。
- AcroForm JS：嵌入受限 JavaScript 引擎，提供明确的 Acrobat API 白名单、执行步数/时间限制和禁网沙箱；补齐 calculate/validate/format/keystroke 事件顺序。
- XFA：短期把能力名称改为“XFA 静态检查与数据导出”；若坚持对齐，需要独立 XFA SOM、布局与事件运行时，成本应单列为长期项目。
- 设计助手先生成多页字段布局提案，用户确认后创建字段；支持对齐、等距、Tab 顺序和字段组。
- 工作表导出生成真正的 `.xlsx`，保留字段类型、日期和多值字段。

**完成标准：** 无域表单识别精确率/召回率均 ≥ 0.9；事件执行顺序与福昕/Acrobat 样本一致；XLSX 通过 Office 打开验证；动态 XFA 未实现前不得写“对齐”。

### 3.5 签名和权限依赖外部路径，缺完整信任体系

**当前降级：** PKCS#12 签名和时间戳透传给 pyHanko；权限管理不能事后独立编辑；对外签章只是本地 PNG；AES 能力依赖带 qpdf 的构建。

**解决方案：**

- 将 pyHanko 固定版本随包发布，主程序通过版本化协议调用；对输入、输出、证书和失败原因做结构化校验。
- 建立 Windows 证书存储、PFX、USB Key/CSP/KSP 的统一证书选择层。
- 完成证书链、撤销状态、时间戳、DocMDP/FieldMDP、增量修改范围和长期验证信息展示。
- 权限面板读取当前加密字典，修改后明确执行“解密并重新加密”，而不是暗示原地改位。
- 区分“图片签章”“数字签名”“平台电子签”；没有服务端时把“对外签章”标为 excluded，而不是 partial complete。

**完成标准：** 与福昕、Acrobat、pyHanko 进行双向签名/验签矩阵；篡改正文、增量批注、证书过期、撤销、TSA 失败均有明确结论；发布包离线可完成 PFX 签名与验签。

### 3.6 高保真转换输入链路不完整

**当前降级：** 网页不执行 JavaScript、不渲染 CSS；剪贴板不处理图片；扫描只支持 WIA 和三种图像；PDF 优化的 Ghostscript 真路径未实跑。

**解决方案：**

- 网页转 PDF 使用隔离的 Chromium/Qt WebEngine 打印管线，支持 CSS、字体、延迟加载和打印媒体查询；提供禁脚本安全模式。
- 剪贴板统一消费 HTML、RTF、位图、文件列表和纯文本；HTML 中的内联图片与 data URI 进入资源解析器。
- 扫描层抽象 WIA/TWAIN 后端，增加 ADF、双面、DPI、色彩、自动裁边、旋转、纠偏和去噪。
- Ghostscript/qpdf 作为受控工具依赖固定版本随包或单独组件安装；CI 必须执行真实优化路径。

**完成标准：** 动态网页、复杂 CSS、剪贴板混合内容、WIA/TWAIN 各至少两台设备；优化后体积下降且页面像素、文字层、书签、链接和表单不丢失。

## 7. 推荐实施顺序

### 阶段 A：先纠正口径（1 个迭代）

- 修改矩阵 schema，加入实现/对齐/验证三轴。
- 将本文件第 6 节的条目降级；把“Markdown PPT”“栅格化转曲”“XFA 静态提取”等改成准确产品名称。
- 为所有 `partial` 增加负责人、目标版本和唯一验收脚本字段。
- CI 检查：备注包含“未做/只有/不支持/未验证/不是”时禁止标记 `aligned`，除非配置了经过审查的例外理由。

### 阶段 B：关闭 P0（建议 4–6 个版本）

1. PDF 解析/写入进程隔离与强制结构校验。
2. 页面对象中间模型和无损保存门禁。
3. DOCX/XLSX/PPTX 高保真转换。
4. 表单识别、完整事件运行时和真正 XLSX。
5. 签名互操作、证书信任与权限管理。
6. 网页、剪贴板、扫描、优化的真实后端验收。

### 阶段 C：专业能力（建议 3–5 个版本）

- 无障碍语义标签与 PDF/UA/PDF/A 外部认证。
- HTML/OFD/CAD、真正矢量转曲。
- 文档比较自动对齐、隐藏信息完整清理。
- 真机设备矩阵和第三方软件互操作实验室。

### 阶段 D：体验收敛

- 手型、区域截图、连续批注、沉浸阅读、完整朗读设置。
- 录制中心、离线帮助、整篇翻译和真正 PPTX 生成。

## 8. 每项功能的统一完成门

每个整改项必须同时满足以下条件，才能重新写成“完成/对齐”：

- 有领域层实现，不依赖按钮槽函数拼业务逻辑。
- 有成功、失败、取消、超时、损坏输入和资源耗尽测试。
- 有保存重开或目标格式重开验证。
- 有至少一个独立软件的互操作验证；核心 PDF 能力使用福昕 + Acrobat/其他独立实现。
- 有复杂 CJK、加密、超大文件和损坏文件覆盖。
- 不静默丢数据；所有降级都必须在执行前展示并允许取消。
- 真实设备/COM/打印/读屏功能有带版本与环境信息的真机证据。
- 发布包中的依赖、许可证、版本、哈希和失败提示完整。
- 文档、矩阵、代码和测试在同一提交中更新。

## 9. 建议新增的自动门禁

1. `check-feature-claims.py`：禁止 `aligned` 行的备注出现未豁免的降级词。
2. `verify-office-interop.ps1`：Office/LibreOffice 重开并抽取结构计数。
3. `verify-pdf-interop.ps1`：本项目写入，福昕/独立解析器重开，比较对象和渲染。
4. `verify-worker-isolation.ps1`：注入崩溃、超时和内存超限，断言 GUI 存活。
5. `verify-device-matrix.ps1`：记录设备、驱动、应用版本与证据文件；没有硬件时明确跳过且发布门不通过。
6. `verify-no-silent-loss.py`：对编辑/转换前后的文字、图片、注释、表单、附件、书签和链接计数。
7. `verify-accessibility.ps1`：UIA + NVDA/JAWS 人工证据清单 + veraPDF 报告归档。

整改工作的核心原则是：**宁可准确地写“部分可用”，也不要用一个成功的窄路径代表整项能力已经与福昕对齐。**
