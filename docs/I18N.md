# 国际化（i18n）

界面语言优先支持中文与英文。中文是**源语言**：代码里 `tr("…")` 里写的就是中文，
中文界面不需要任何翻译文件；英文等其他语言各有一份翻译目录。

## 目录与命名

| 位置 | 作用 |
|---|---|
| `src/i18n/ai-pdf-editor_en.ts` | 英文翻译目录（Qt Linguist 标准 `.ts` 格式） |
| `src/app/Language.{h,cpp}` | `.ts` 运行时解析器 + 语言管理器 |
| `src/i18n/Translate.h` | 非 QObject 代码的翻译入口、界面文案登记表 |

`.ts` 通过 `qt_add_resources` 打进 `:/i18n/`，运行时由 `TsTranslator` 直接解析。

**为什么不用 lrelease。** 固定工具链里只有 qtbase + qtsvg，没有 Qt LinguistTools。
为了不把「装好工具链就能构建」这条前提打破，程序自己解析标准 `.ts`：
目录格式仍是 Qt Linguist 能直接打开编辑的标准格式，也没有多出一个 `lrelease`
构建步骤。新增语言只要放一份 `ai-pdf-editor_<code>.ts`，再在
`Language.cpp` 的 `supportedLanguages()` 里登记。

## 写界面文案

规则：**每条 `tr()` 的参数必须是字符串字面量**。只有这样
`scripts/check-i18n.py` 才能静态核对「有没有漏翻」，`tr(变量)` 一律不写。

1. 一次设定、长期显示的文案（菜单、按钮、标签、停靠面板标题、工具提示）：
   用 `texts_.bind(...)` 登记，切换语言时就地重译。

   ```cpp
   texts_.bind([this, action] { action->setText(tr("打开 PDF…")); });
   ```

2. 每次刷新都会重新计算的文案（状态栏消息、页数标签、错误提示）：
   直接 `tr("…")`，不需要登记。

3. 文本要当参数传给别的函数（比如占位页的标题），调用点用
   `QT_TRANSLATE_NOOP("上下文", "中文")` 把源文案带下去，收的一侧用
   `tr(source)` 现翻，并把这段登记进 `texts_`。

4. 非 QObject 代码（`doc/`、`ai/`、`pdf/`、`ocr/`、`tools/` 里的自由函数与结构体）
   用 `i18n::tr("aipdf::pdf::Annotation", "高亮")`：上下文写成稳定的
   命名空间 + 类型名，和 `.ts` 里的 `<context>` 一一对应，重构搬家不会丢词条。

5. 保留占位符（`%1`、`%2`）与快捷键（`&F`）。翻译里可以换语序，不能少占位符。

6. 每个带界面文案的类在自己的构造函数里接上重译：

   ```cpp
   connect(&i18n::LanguageManager::instance(), &i18n::LanguageManager::languageChanged,
           this, &Klass::retranslateUi);
   ```

   `retranslateUi()` 里先 `texts_.retranslate()`，再把随状态变化的提示
   （比如「有选区才能解释」）交给各自的 `update*()` 重新算一遍。

## 不要翻译的东西

- 日志与非界面诊断：`qWarning()`、`qDebug()`、`trace(...)`、审计日志字段；
- 发给模型的提示词（system prompt）与工具名、JSON 键；
- 写进 PDF 文件本身的内容：注释字典、外观流、XFDF 元素名；
- 文件名、扩展名、Tesseract 语言代码、命令行开关；
- `QSettings` 的键与内部状态值（`"Accepted"`、`"applied"` 之类）。

## 语言选择

- 默认「跟随系统」：系统语言是中文就用中文，其他语言回退到英文。
- 主窗口 ☰ 菜单 →「语言」里可以手动切换，选择存 `QSettings` 的 `ui/language`
  （`"system"` 或语言代码）。
- 探针模式（`AIPDF_TRACE_FILE`）用独立的设置目录，验收脚本不会冲掉用户的选择。
- 环境变量 `AIPDF_UI_LANGUAGE`（`zh_CN` / `en` / `system`）可以钉死本次运行的界面语言，
  **不写进设置**。验收脚本靠它保证断言面对的语言是确定的：
  `scripts/AcceptanceProbe.ps1` 会把界面语言固定成中文。

## 用户侧安装语言包

语言包原先只在构建期打进 Qt 资源，用户侧装不了别的语言。现在有一份**用户级可写目录**：

```
%LOCALAPPDATA%\AI PDF Editor Project\AI PDF Editor\translations
```

- **两个入口**：设置 →「界面语言」→「安装语言包…」与主菜单「语言 → 安装语言包…」；
- **流程**：选 `.ts` 文件 → 校验 → 复制到上面那个目录 → 切到该语言 → 提示结果；
- **校验四件事**：
  1. 能解析成目录且词条非空（否则装进去也是坏的）；
  2. **是本应用的目录**（上下文里有 `aipdf::app::` 的词条）——
     装一个别人的 `.ts` 进来，界面一个字都不会变，装之前就该拦住；
  3. **目录自己声明的语言与目标一致**（装错语言包比不装更糟：
     界面会变成另一种语言，用户还以为是自己刚装的）；
  4. 语言代码得像个语言代码（`ja`、`zh_CN` 这类）。
- **用户目录优先于程序自带**：用户装了新语言包就该用用户的，不能被程序自带的压住；
- **装了就能选**：新装的语言进 `availableLanguages()`，语言菜单与设置下拉当场多出这一项；
- **缺包时给可执行引导**：说清包名、目标目录与两个安装入口，不只报一句错。

## 验证

```powershell
# 单元测试：
#   .ts 解析、语言解析与回退、切换与持久化、环境变量覆盖（I18nTests）
#   真实控件切换语言后就地重译（I18nWidgetTests）
#   语言包的用户侧安装 / 切换 / 缺包引导（LanguagePackTests）
ctest --test-dir build/windows-debug -R I18n
ctest --test-dir build/windows-debug -R LanguagePack

# 覆盖率：源码里的每条 tr()/translate()/QT_TRANSLATE_NOOP 都要有英文翻译
python scripts/check-i18n.py

# 界面验收：中文界面 / 英文界面 / 记住选择 / 覆盖率，四种情况走真实进程
powershell -ExecutionPolicy Bypass -File scripts/verify-i18n.ps1
```

ctest 里挂了三份：`I18nTests`、`I18nWidgetTests` 与 `I18nCoverageTests`
（最后一份就是 `check-i18n.py`，漏翻会让整条流水线红）。

`check-i18n.py` 会报出四类问题：漏翻（源码里有、目录里没有）、空翻译、
上下文对不上（目录里有这条文案但登记在别的上下文，运行时会查不到）、
目录里有但源码里已经找不到的陈旧词条。前两类与「上下文对不上」会让退出码变成 1。
